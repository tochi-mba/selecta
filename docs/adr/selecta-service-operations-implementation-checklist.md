# Selecta Service Operations implementation checklist (ADR-0470 to ADR-0474)

**Task status:** 30 tasks: 0 Implemented, 5 In progress, 25 Not started, 0 independently Verified.

**Status:** Five proposed ADRs written on 2026-11-20. They refine ADR-0410 without changing its accepted SLOs or emergency-control contract. Existing admin health scaffolding is recorded as In progress, never as working production monitoring.

**How to tick a box.** Tick `[x]` only after the acceptance statement is true and the required verification has run. The line must then name implementation evidence. A mock response proves UI handling, not real provider monitoring. Staging evidence is required wherever stated.

## [ADR-0470 - Live dependency health, readiness and synthetic probes](adr-0470-live-dependency-health-and-readiness.md)

- [ ] **OP-0470-01 - Dependency registry.** Acceptance: one typed registry covers Render API/gateway/maintenance, Postgres, every required R2 bucket, Modal, WorkOS, Stripe, Anthropic, Resend, Grafana and Sentry with owner, criticality, environment, probe, timeout, freshness, runbook and safe-mode consequence. Required verification: registry completeness test against deployment configuration. Implementation: In progress; six names exist in `admin.read_models.REPORTED`, but the registry and five dependencies are absent. Independently verified: No.
- [ ] **OP-0470-02 - State and freshness contract.** Acceptance: every dependency reports healthy, degraded, down, unknown or not_configured; stale and absent measurements never become healthy. Required verification: unit/property tests including clock skew and missing readings. Implementation: In progress; generic fresh/stale/unknown readings exist, but dependency states do not. Independently verified: No.
- [ ] **OP-0470-03 - Process health endpoints.** Acceptance: API, gateway and maintenance expose distinct liveness/readiness behavior; liveness has no vendor dependency and readiness names failed required components without secrets. Required verification: integration tests for each dependency failure. Implementation: Not started. Independently verified: No.
- [ ] **OP-0470-04 - Storage and compute probes.** Acceptance: Postgres, each R2 bucket and Modal are measured through bounded environment-specific canaries, with latency and failure class reported. Required verification: staging credential-expiry, missing-object, timeout and no-worker drills. Implementation: Not started. Independently verified: No.
- [ ] **OP-0470-05 - Identity, billing, AI and email probes.** Acceptance: WorkOS, Stripe, Anthropic and Resend use non-customer, non-billable safe checks and distinguish authentication, rate-limit, configuration and outage failures. Required verification: provider test environments plus injected response tests. Implementation: Not started. Independently verified: No.
- [ ] **OP-0470-06 - Telemetry probes.** Acceptance: Grafana export success/queue/drop state and a bounded Sentry ingestion canary are measured without making the app depend on either provider. Required verification: staging rejection and black-hole drills. Implementation: Not started. Independently verified: No.
