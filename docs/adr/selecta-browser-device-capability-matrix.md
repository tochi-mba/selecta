# Selecta Cloud — cross-device/browser feasibility and DSP migration matrix

**Researched:** 2026-11-14. **Authority:** [ADR-0485](adr-0485-browser-first-cloud-and-ipad-venue-runtime.md). **Status:** engineering plan, **not** hardware certification or a claim that browser DSP exists today. These are baseline expectations, not a guarantee for every model/browser build. Re-test on real devices.

## The non-negotiable product experience

Selecta Cloud is an **HTTPS, no-companion-install browser product**. No venue needs a dedicated Windows/Mac/Linux computer or Python/FFmpeg daemon: a single iPad **or Android tablet** may be the actual DJ and audio output. Phones, laptops, desktops, Chromebooks and tablets can be players when they own authorised, device-accessible media and pass output/performance tests; otherwise they work as editors, guests or remote controllers. The standalone Python Selecta product remains separate and installable.

The browser receives application code, permissible model weights and WASM modules over HTTPS (normal site downloads, **not a user-installed engine**). Audio files/decoded PCM/stems/exports stay on the playing device. Cloud syncs only metadata, recipes, permissions, schedules, approved AI plans, requests and command acknowledgments.

**Hard operational distinction:** “iPad/Android tablet playing in the foreground while powered and awake” is a realistic browser-venue target. “Music survives closing the page, OS task killing, device reboot or arbitrary screen lock indefinitely” is **not** an honest generic browser promise. Introduce an optional separately licensed/kiosk/native deployment only for **advanced unattended requirements**, never as the default Cloud requirement.

Do not secretly run protected recordings on cloud workers to fill missing mobile features.

## Matrix C — platform APIs and hard compatibility distinctions

| Requirement | Current research and risk | Selecta implementation contract |
|---|---|---|
| AudioWorklet | Supported in modern Chrome/Edge, Firefox, Safari, Chrome Android, Samsung Internet and Firefox Android; device/browser audio glitches still exist | Mandatory for sophisticated browser DSP; runtime test worklet loads and processes a synthetic block at target rate |
| Browser/WASM SIMD/threads | WASM common; SharedArrayBuffer/multithread requires cross-origin isolation and coordination with login/third-party resources | First launch single-thread-safe; enable worker/SIMD/threads only when detected and validated |
| WebGPU / neural | Android Chrome WebGPU since Chrome 121 on supported Android 12+ ARM/Qualcomm GPUs; compatibility mode broadens possibilities; Safari 26 has WebGPU. | File picking | File inputs widely available. Safari iOS/iPadOS 18.4 added `webkitdirectory`. Chrome Android 132+ supports File System Access picker APIs in relevant builds. Firefox Android / Samsung Internet have **different** directory/handle support | Capability-test `showDirectoryPicker`, `webkitdirectory`, file input and re-access; retain a pick-files fallback on every supported phone/tablet; never hard-code Safari-only or Chrome-only solution |
| Storage | OPFS/IndexedDB/Cache Storage quota and eviction differ; app or site data may be cleared; private mode ephemeral | No source-file loss; quota/persist/storage-pressure probes, eviction handling, staged downloads and re-import UI |

## Android-specific qualification programme (required; not one generic Android pass)

- **Browser engines:** Chrome stable (and installed PWA), Samsung Internet stable, Firefox Android, Edge/Opera where supported; Android WebView/in-app browsers are controller-only until proven.
- **Hardware bands:** 3–4 GB low-memory tablet/phone; 6–8 GB mid-range; modern 8–12+ GB tablet/flagship; different Qualcomm Snapdragon, MediaTek, Exynos, Tensor or other GPU families. Device memory reporting may be unavailable or imprecise.
- **Android releases and OEMs:** test recent supported Android major versions; Samsung One UI, Google Pixel, Lenovo/other tablets and Xiaomi/Oppo/Honor-style aggressive battery policies. Every device record includes OS, chipset, RAM, browser build, power mode and thermal state.
- **Posture:** phone portrait + tablet landscape; Chrome tab vs installed PWA; Samsung DeX desktop layout where supported; screen awake/locked; split-screen/multi-window; app switching; low-power mode; device charging; Android Doze.
- **Audio:** phone calls, notification, voice assistant, other media app, headset unplug, Bluetooth speaker disconnect/reconnect, USB DAC and dock/HDMI, device volume, absolute-volume mismatch; verify sound physically.
- **Media:** Files document provider, USB/SD-card accessible files, selected folder, 5/8 missing tracks, permissions revoked, cloud drive not cached offline, unsupported format; **never assume access to Spotify/YouTube Music**.
- **Stress:** long sessions, heat, low battery, model downloaded mid-set, Safari-equivalent browser memory pressure, slow/poor network, browser update, site-data cleanup, offline policy and rooms replay.
- **Output:** one active venue output initially; separate multizone only with real hardware and verified routing. Chromecasting isn't automatically a destination for arbitrary local Web Audio PCM.

## iOS/iPadOS-specific qualification programme

- iPadOS Safari tab and Home Screen web app; older supported A-series tablet and M-series iPad; iPhone Safari used as player and controller.
- Safari 18.4+ directory input changes, Files and external USB-C drive provider, local storage quota/eviction, wake lock on Home Screen, Web Audio interruption and silent playback bug regression, `AudioContext.setSinkId` absence, touch gestures and rotation.
- Screen lock/auto-lock, app switch, power, Guided Access as optional, Bluetooth/AirPlay/USB-C/HDMI speaker, Sleep Focus/notifications, restart and safe user-gesture re-entry. Never promise iPad background service or automatic restart.

## General acceptance benchmark (record actual numbers; do not invent thresholds)

For each advertised profile and **actual model/browser/OS tuple**, record cold start; file-picker import time; 50/500/5,000 track metadata scan; peak memory/storage; audio callback glitches and scheduling misses; prepared transition horizon; BPM/key confidence vs golden offline reference; effect and timestretch distortion; 15s and full-song neural stem timing/thermal; FLAC 5/30/60 minute export duration/checksum; 6-hour powered awake venue soak; network outage/recovery; output disconnect; background/lock; phone call/audio focus; multi-tab fencing; offline local recipes; UX accessibility; privacy egress capture.

Define per-feature acceptance thresholds from human listening and real-world devices. If an OS/browser lacks a test result, its status remains **unknown/unqualified**, not a product claim. Store the outcome by `device_model + os_version + browser_engine/version + engine_version + codec + media_source + output_type`, and show *why* the feature cannot be enabled.

## Architecture/repository consequences

1. Build a **browser engine** layer (WebAudio/AudioWorklet real-time, JS/WASM deterministic DSP, workers/model adapters, local OPFS or safe file handles). Cloud must not require `src/selecta/local_engine/**` or any installed Python service to play.
2. Cloud API should register browser playback sessions, not only native devices; phones can control tablets; sessions have TTL and playback ACK; true speaker requires audibility check.
3. Keep separate standalone Python mode; use its algorithms/tests as reference while porting DSP. Existing native-focused LF agents 01/02/03/04/05/06/07/08/09/12 and venue UI prompts need **re-scoping** before integration: no silent native dependency.
4. Add device browser compatibility harness with synthetic owned audio, offline/visibility/outputs and actual iPad/Android hardware. Reject mock-only evidence for venue claims.
5. Rewrite onboarding, player and venues: Connect Music → Verify Locally → Check Browser Capability → Choose Output → **Tap Start** → Audible Sound Check → **Keep Awake** → Remote Controller optional. No mandatory Install Engine or Pair Desktop.
6. Distinguish clearly between **browser venue (supervised while active)** and **separately approved optional unattended product**, avoiding universal auto-resume assurances.
7. Update release gates, source map, UX contract, ADR, security threat model, legal compliance and task evidence. No production media route retirement until negative egress tests pass.

## Research caveats

- Browser API-support tables differ by release; `showDirectoryPicker` and related Android picker support have changed recently. Feature-detect, **test devices**, and avoid hardcoded assumptions.
- Safari 26 enables WebGPU at browser level, while the current ONNX Runtime Web compatibility table still lists Safari WebGPU as unavailable; treat **library support** as a separate certification step.
- One open WebKit bug report is evidence of a real class of failure, **not** proof every iPad model or current Safari release is affected.
- This document deliberately does **not** certify browser-native replacements for PyTorch/Demucs/Beat This, guarantee locked-screen DJ playback, or represent physical audible-output tests.
