# Local-first Cloud status and browser-first supersession

**2026-11-14 owner clarification:** [ADR-0485](adr-0485-browser-first-cloud-and-ipad-venue-runtime.md) requires **no-install browser-native Cloud playback on qualified desktop browsers, iPads and Android tablets**, including venues with only one tablet. Any LF ADR requiring a Python engine installation, companion desktop or guaranteed unattended background browser operation is superseded in that respect. The standalone native Python product retains its own guarantees.

**Status honesty:** ADR-0455–0484 are existing architecture decisions. Their original checklist statuses were a documentation snapshot, **not** proof that PR #64 lacks implementation: substantial native-oriented work was subsequently added. Equally, that Python code **does not prove** browser-native Web Audio DSP, neural-model parity or iPad/Android venue sound reliability. The 136-task LF checklist now includes 16 explicit ADR-0485 browser/device gates, all requiring source, tests, device evidence and independent review. No automatic ticks based on ADR prose.

**No current customers:** Do not fabricate customer-migration obligations; still preserve historical source/code, existing standalone mode, developer/test data, legal records and reversibility. Hosted R2/Modal user-audio infrastructure may be safely removed only after verifying no production material requires preservation and cloud egress and negative tests are complete. No production teardown is authorised by documentation edits.

**Priority blockers:** JS/WASM/AudioWorklet audio engine missing; Beat This/PyTorch, librosa/SciPy, Pedalboard time-stretch, Demucs and wav2vec2 not ported to browsers; local file import and cache persistence differ; one-venue-tablet physical output untested; iPadOS and Android browser process lifecycle; Cloud-to-live-browser command and UI wiring not complete. Some existing native LF code may be reusable as standalone/reference but is not a Cloud dependency.

**Capability requirement:** distinguish supported, unsupported_here, permission_required, no_source, degraded, output_unverified, interrupted, uncertain and ready. A playlist or Cloud ACK is never real audio output proof. Internet outage can allow current browser to continue if active and prepared; it cannot make a closed/rebooted mobile browser run jobs.

Older hosted-audio docs retain historical records but must not govern new implementations.
