## Context and evidence boundary

The real engine is Python: Beat This and PyTorch for beats, a neural checkpoint for key, librosa/SciPy feature extraction, pedalboard time-stretch, Demucs stems, FFmpeg decode, and the seam renderer. None of that runs in a browser because the UI is React; `torch`, `demucs`, `librosa` and `pedalboard` have no magic Safari builds. What is honestly portable, per the 2026-11-14 research: Web Audio graphs with AudioWorklet everywhere that matters; JS/WASM FFT, mel, MFCC, chroma and segmentation; loudness, true peak and limiting as ports with golden tests; scripted transitions as ahead-of-time windows. What is conditionally portable: neural beat and key models, high-quality time-stretch, stem separation and word alignment, each needing model conversion, per-device memory/thermal/runtime evidence and licence checks.

No browser DSP exists on `main`. Every parity claim below is defined by measurements that have not been run.

## Decision

- **Three tiers, flag `cloud.browser_dsp` beyond baseline.**
  - **Tier 1 - baseline, every qualified player:** decode, two-deck playback, crossfade, EQ and filters, loudness/true-peak limiter, prepared fades. This is what "can play" means; a device that cannot do Tier 1 is a controller (ADR-0460).
  - **Tier 2 - measured devices:** lightweight beat/onset/tempo and key estimates, scripted beatmatched seams in bounded ahead-of-time windows, bounded pitch-preserving time-stretch, reverb/echo/energy effects within a CPU budget, seam preparation in workers with a short prepared horizon.
  - **Tier 3 - per-device benchmark plus model licence:** neural beat tracking, neural key, stem separation, word-level lyric alignment and the features built on them (stem intertwining, word cuts). Each Tier 3 feature needs recorded per-device memory, thermal and runtime evidence and a licence check before it can switch on anywhere.
- **Honesty rules.**
  - A lighter method is a *different verified implementation or an explicit reduced capability*, never silently "the same feature". The interface and the capability record both say which implementation produced a result.
  - `unsupported_here` is a first-class state with a reason, not an error.
  - Confidence is carried with every analysis result; a low-confidence beat grid refuses beatmatched seams rather than cutting badly.
  - No cloud compute quietly fills a device gap for default accounts (restates BF-0455-04).
- **Local mode's moves in a browser mix (flag `cloud.browser_moves`, added 2026-11-19).** A browser seam asks for a move like a local one. With no move chosen SelectaDJ picks in local mode's preference order (`planner/choose.py` `_style_fit`): a beatmatched bass swap blend first, then a filter sweep, and when no beatmatched overlap of at least 8 bars fits, the tempo-free moves with echo out as the universal fallback, then a cut. It picks only among moves whose `move.*` flags are on, and only what the device measured and can do; each pick carries a plain reason. The member may choose bass swap blend, filter sweep, cut, echo out or reverb wash per seam; the choice is saved in the recipe seam's settings, belongs to the two songs it joins, and follows them through a reorder. Echo out and reverb wash use Web Audio returns (`web/src/dsp/seamEffects.ts`, a delay loop and a generated room) under their own implementation id, never claimed to be the Python renders. Exits default to an 8-bar phrase line of the outgoing song's grid. The editor says what each seam really scheduled this visit, including any fallback and why; nothing is stored. Moves that need lyric timing (word moves, delay throw) stay off in the browser. The stem moves (vocal ride, strip and land, intertwined stems) are built behind `cloud.browser_stems` and wait on Tier 3 below.
- **Time-stretch, not a speed nudge (BF-0459-05, 2026-11-19).** The playbackRate nudge that was built behind `cloud.browser_varispeed` is removed with its flag. Instead the incoming song's opening is pre-rendered with the self-tested WSOLA stretch (`web/src/dsp/stretch.ts`) in a worker, at the outgoing song's tempo, plays as a clip through the overlap and a 16-beat ease back to its own tempo, then hands over to its own audio with a 30 ms crossfade, as the Python engine's `in_context` does. Only the incoming song moves (up to 8 percent); local mode meets both songs at the geometric mean beyond 3 percent, which in a browser would mean swapping the song already playing for a clip. The longest overlap is 32 s (`MAX_WINDOW_SECONDS`), so blends run 16 bars at 120 BPM as in local mode. A stretch that can't be prepared falls back to the drift-bounded overlap or a fade, and the editor says why. Tempo ramp becomes possible (only the incoming song drifts).
- **Parity is measured, not asserted.** The Python engine renders a golden set from synthetic owned audio: beat grids, keys, LUFS, true peak, seam timings and rendered seams. The browser engine renders the same set; the comparison harness scores them, and listening tests on supported desktop and tablet close the loop. The owner's listening judgement stays the final musical gate, as everywhere in this project.

## User outcome and acceptance contract

On a capable device a member gets mixes that sound like SelectaDJ: beatmatched where the analysis is confident, graceful fades where it is not, loudness-safe always. On a weaker device they get fewer tricks, told plainly, never a worse-sounding imitation of a trick the device cannot afford. Nothing ever claims to be the neural engine's output when it is the lightweight estimate.

## Edge cases

- **Confident-looking nonsense.** A lightweight tempo estimate that is exactly double or half the truth: the seam scripter treats half/double-time ambiguity as low confidence and falls back to fades (the known steady-beat cases from the request-chain work).
- **Thermal collapse mid-set.** Benchmark-calibrated budgets shrink the prepared horizon and effect count before the callback starves; the member sees the simplified state, audio never glitches as the first symptom.
- **A Tier 3 model downloaded mid-set.** Model loading never competes with the audio callback; activation waits for a seam boundary.
- **Imported analysis cache from another device.** Results carry the implementation and version that produced them; a device never serves another tier's cached result as its own capability.
- **Format oddities.** Variable bitrate, odd sample rates, mono files: resample and channel-map through tested paths; golden set includes them.
- **Licence refusal.** A Tier 3 model whose licence fails review simply never ships to browsers; the feature stays `unsupported_here` everywhere rather than shipping unlicensed.

## Rejected alternatives

- **Porting the Python stack wholesale to WASM.** PyTorch, librosa and pedalboard are not browser libraries; pretending otherwise produced the abandoned branch's false readiness. Ports are per-algorithm with golden tests.
- **Server-side analysis for default accounts.** Breaks the no-audio contract; rejected.
- **One quality bar for all devices.** Forcing Tier 1-only everywhere wastes capable desktops; forcing Tier 2 everywhere lies on budget phones. Tiers with honest labels are the design.
- **Calling browser output "the same mix" as native.** Until the harness and listening tests say so for a given tier and device class, it is not claimed.

CI verification remains pending. **Independently Verified:** No.
2. **BF-0459-02 - Tier 1 engine.** **Acceptance:** Decode, two-deck crossfade, EQ/filters, loudness/true-peak limiter and prepared fades run in the ADR-0457 runtime with golden LUFS/peak/clip tests against the Python reference. **Required verification:** CI harness on three browser engines with recorded numbers. **Implementation:** Implemented: crossfade, EQ and filters, loudness and true-peak limiter (`web/src/dsp/`, `web/src/engine/limiter.ts`, worklet limiter); `goldenSet.test.ts` contains LUFS, peak and clip comparisons against the Python reference. The three-engine CI run with recorded numbers is pending. **Independently Verified:** No.
3. **BF-0459-03 - Lightweight analysis.** **Acceptance:** JS/WASM onset/tempo/key/feature estimates with confidence, versioned schema, half/double-time ambiguity treated as low confidence; accuracy vs the golden set recorded, not asserted. **Required verification:** Harness scores checked into evidence. **Implementation:** Implemented: onset, tempo and key estimates with confidence in `web/src/dsp/analysis/`; near-tie half/double-time is treated as low confidence. The golden-set harness contains accuracy comparisons; checked-in evidence scores remain pending. **Independently Verified:** No.
4. **BF-0459-04 - Scripted seams.** **Acceptance:** The seam script semantics port for bounded ahead-of-time windows; low confidence falls back to fades; seam timing parity vs reference within the recorded tolerance; `leave_after` (30 s settle rule) honoured. **Required verification:** Golden seam renders plus the owner's listening pass. **Implementation:** In progress: `web/src/dsp/seams.ts`, `seamScript.ts` and `seamProvider.ts` prepare bounded worker-backed schedules, with fades on low confidence and the 30 s `leave_after` rule; `web/src/cloud/localFirstPlayer.ts` wires the provider into the runtime. Tier 2 now requires a fresh per-device worker calibration, enforces its deadline per analysis block, shrinks the next analysis window after misses, and becomes unsupported at budget exhaustion. Without calibration or after expiry, playback stays on the labelled fade path. Golden seam parity and the owner's listening pass remain pending. **Independently Verified:** No.
5. **BF-0459-05 - Bounded time-stretch.** **Acceptance:** Pitch-preserving stretch within ratio and window limits via WASM DSP; naive playbackRate pitch shifts are never used for musical stretch; quality acceptance from listening plus transient-smearing measurements. **Required verification:** Harness plus listening pass. **Implementation:** Implemented, not listened to: a WSOLA stretch in TypeScript rather than WASM (`web/src/dsp/stretch.ts`, ratio curve for the ease back, 0.92 to 1.08, 60 s input), run in `workers/stretchWorker.ts`, self-tested at engine start (`stretchLoader.ts`), and played through the scheduler's clip-then-native handover (`engine/scheduler.ts`). `STRETCH_PLAYBACK_INTEGRATION` now means "self-tested on this device and the scheduler handover is wired", since a seam needs the ability before one can be scheduled. Compared with the Python reference (pedalboard Rubber Band) on the shared synth at 0.95 and 1.05: length exact, all hits found, pitch within 0.5 percent, hits within 12 ms (`golden.test.ts`); not sample-equal, by design. Needs a person: the owner's listening pass. **Independently Verified:** No.
6. **BF-0459-06 - Worker scheduling and horizon.** **Acceptance:** Analysis and seam preparation run in workers under a benchmark-calibrated budget that never steals callback time; the prepared horizon degrades before audio does; deadline misses are counted and surfaced. **Required verification:** Scheduling tests with synthetic load, device-lab soak numbers. **Implementation:** Implemented: analysis and seam preparation use workers (`web/src/dsp/workers/analysisWorker.ts`, `web/src/dsp/seamProvider.ts`); `web/src/dsp/budget.ts` shrinks the prepared horizon and counts deadline misses. The scheduler disposes the seam provider and its worker during teardown. Device-lab soak numbers and CI verification remain pending. **Independently Verified:** No.
7. **BF-0459-07 - Tier 3 evaluation protocol.** **Acceptance:** A written per-model protocol (conversion route, memory/thermal/runtime measurements per device class, licence review, quality comparison) that any Tier 3 candidate must pass; no Tier 3 feature ships before its protocol record exists. **Required verification:** Doc review plus the first completed record. **Implementation:** In progress: [the protocol and per-candidate evidence template](../verification/bf-tier3-evaluation-protocol.md) define licence gates, conversion equivalence thresholds, per-class physical-device memory/runtime/thermal/battery measurements, golden-set quality thresholds, owner listening, and an enable/unsupported decision record. ## Governance

Accepted by the owner on 2026-11-17. The owner's listening judgement is the final gate on any claim that a browser seam or stretch "sounds right" (BF-0459-04, BF-0459-05); automated parity numbers alone never flip those tasks.
