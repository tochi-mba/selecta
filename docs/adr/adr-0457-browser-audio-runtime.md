## Context and evidence boundary

Cloud playback on `main` streams presigned proxy URLs through an HTMLAudioElement (`web/src/cloud/useCloudPlayer.ts`, `web/src/devices/audioSpeaker.ts`); the browser never decodes or mixes. The local web app has a real player (`web/src/player.ts`) but it is driven by the local Python server. The docs/saas/05 section 5.8 description of browser `decodeAudioData` playback is aspirational, not what the code does.

The decision below creates the first actual audio engine that runs entirely in the member's browser. No browser audio engine exists on `main`; nothing here is implemented or measured. Device and OS behaviour claims come from the research checked on 2026-11-14 (AudioWorklet availability, WebCodecs limits, the WebKit 2026 silent-output class of failure) and must be re-verified on real hardware under ADR-0466.

## Decision

- **One runtime, flag `devices.browser_player`.** A browser engine layer in `web/src/engine/`: an AudioContext and AudioWorklet graph for real-time playback, deterministic DSP in workers (WASM where measured), and decode through the browser codec stack plus vetted WASM decoders where a needed codec is missing. It registers with Cloud as a playback device through the existing device and session machinery (ADR-0415), so Rooms, remote control and take-over treat it like any speaker.
- **Foreground, gestured, single owner.** Audio starts only from a fresh user gesture. Exactly one tab owns the account's (or zone's) audio at a time: the ADR-0419 single-audio-owner contract extends to browser sessions, with fencing in ADR-0461. The runtime watches visibility, wake-lock revocation, interruptions and device changes, and reports them truthfully; a hidden or suspended tab never claims to be playing.
- **Capability probe before any claim.** At startup the runtime loads a test worklet and processes a synthetic block at the target rate. Only a passing probe lets the device present itself as a player; failing devices get controller and library surfaces with the reason shown (ADR-0460). A probe pass is still not an audibility claim: physical output needs the sound check.
- **Local render and export, flag `cloud.local_export`.** Offline rendering runs in the browser (OfflineAudioContext or worker DSP) and exports WAV and FLAC. FLAC is written by SelectaDJ's own TypeScript encoder (`web/src/engine/flac.ts`, fixed predictors with Rice coding), not a WASM one, since WebCodecs AudioEncoder does not produce FLAC or MP3; every FLAC is checked by decoding every frame, checking every CRC and comparing the decoded audio's MD5 with the one the encoder stored (`flacDecode.ts`). MP3 is not offered. Exports are chunked, checksummed, duration-validated and cancellable, and download through an explicit member action (mobile Safari needs the explicit tap).
- **No hidden fallback.** When a default account's device cannot do something, the answer is `unsupported_here` with a reason. The runtime never uploads audio, never proxies PCM through Cloud, and never runs a member's protected recordings on cloud workers to fill a gap.
- **Hosted playback unchanged.** `useCloudPlayer.ts`, `CloudListen.tsx` and the presigned-proxy path remain the hosted mode's player (ADR-0456); this runtime replaces them only for local-first accounts.

## User outcome and acceptance contract

A member taps play and hears their own file mixed in the browser with no install, no upload and no spinner waiting on a worker. When their device cannot do something, the interface says so plainly and offers what does work. An export is a real file on their device whose checksum and duration were validated before they were told it succeeded.

## Edge cases

- **Context interrupted.** Phone call, assistant, another app taking audio focus, or an OS interruption: the runtime pauses, reports `interrupted`, and resumes only from a fresh gesture where the platform requires one.
- **Output route changes.** Headset unplug, Bluetooth disconnect, USB DAC removal: playback pauses safely (no blast on route change), state downgrades to `output_unverified` until re-checked.
- **Tab discarded or crashed.** The session lease (ADR-0415 heartbeat) expires; remote controllers see `uncertain`, never a stale `playing` (ADR-0461).
- **Running but inaudible.** The WebKit 2026 class of failure where the graph runs with signal and nothing is audible: analyser data never upgrades status; only the human sound check does (ADR-0460).
- **Decode failure.** An unsupported or corrupt file reports a clear per-file error and is excluded from mixes; the engine never substitutes silence inside a seam.
- **Memory pressure.** Decoded PCM is capped and evicted least-recently-needed; a long queue cannot grow unbounded; the prepared horizon shrinks before the tab dies.
- **Two tabs race.** The second tab asking to play gets a take-over prompt, not concurrent audio (fencing in ADR-0461).
- **Export interrupted.** A cancelled or failed export leaves no half-written file presented as complete; partial state is discarded and reported.

## Rejected alternatives

- **HTMLAudioElement playback for local files.** Media elements cannot run transitions, EQ or a limiter; the whole point is a mixing engine. Kept only as the hosted mode's player.
- **A service worker as the DSP engine.** Service workers are killable and throttled; they may cache the shell but cannot promise uninterrupted audio. The engine lives in the page and its workers, foreground.
- **Requiring SharedArrayBuffer threads at launch.** Cross-origin isolation interacts with login and third-party resources; first launch is single-thread-safe, threads and SIMD enabled only when detected and validated.
- **Transparent cloud compute fallback.** Explicitly rejected: it would silently break the no-audio-egress contract (BF-0455-04) and the member's privacy expectation.

## Implementation checklist - 4/8 Implemented; 4/8 In progress; 0/8 independently Verified

1. **BF-0457-01 - Engine skeleton and flag.** **Acceptance:** `web/src/engine/` holds the runtime (context lifecycle, graph, worklet loader, state machine) behind `devices.browser_player` (registered, default off, `docs/flags.md` regenerated); with the flag off nothing loads. **Required verification:** Vitest unit tests, `tests/test_flags.py`. **Implementation:** Implemented: `web/src/engine/` (context, graph, worklets, state machine, scheduler) behind `devices.browser_player` (default off, in `docs/flags.md`). CI verification remains pending. **Independently Verified:** No.
2. **BF-0457-02 - Capability probe.** **Acceptance:** The probe loads a worklet, processes a synthetic block at target sample rate, measures scheduling misses, and gates the player surface; failures render the controller experience with the recorded reason. **Required verification:** Vitest plus Playwright runs in Chromium, Firefox and WebKit engines asserting real (not mocked) worklet execution. **Implementation:** Implemented: `web/src/engine/probe.ts` runs the worklet probe and `web/src/cloud/localFirstPlayer.ts` refuses with the recorded reason. The three-engine Playwright run of the app probe is pending (see BF-0466-03). **Independently Verified:** No.
3. **BF-0457-03 - Gesture, focus and visibility truth.** **Acceptance:** Playback starts only from a fresh gesture; visibility loss, wake-lock revoke, interruption and route change each produce the correct state (`interrupted`, `output_unverified`, `uncertain`) visible to the member and to remote controllers. **Required verification:** Playwright interruption tests; device-lab evidence under ADR-0466. **Implementation:** In progress: `web/src/engine/context.ts`, `speakerAdapter.ts` and `state.ts` downgrade hidden-tab output to `uncertain`, pause safely on output-route changes and report `output_unverified`, and downgrade to `uncertain` when a previously granted wake lock is revoked. `web/src/devices/usePlaybackDevice.ts` detects wake-lock loss and sends truthful output status with each 5-second playback heartbeat. Context/speaker teardown is idempotent and closes owned resources. Playwright interruption tests and ADR-0466 hardware evidence remain pending. **Independently Verified:** No.
4. **BF-0457-04 - Decode and memory budget.** **Acceptance:** Decode through the codec stack with per-file error reporting; decoded PCM capped with eviction; a 5,000-track queue session stays inside the measured budget on the reference devices. **Required verification:** Unit tests plus recorded device measurements. **Implementation:** Implemented: `web/src/engine/loader.ts` decodes with per-file failures and evicts the stalest PCM with counted evictions. The 5,000-track measurement on reference devices is pending. **Independently Verified:** No.
5. **BF-0457-05 - Device registration.** **Acceptance:** The runtime registers as an ADR-0415 playback device (lease, heartbeat, reconnect); `web/src/devices/usePlaybackDevice.ts` drives it; hosted and browser players never both claim one session. **Required verification:** `tests/test_cloud_playback_*.py` extensions, vitest. **Implementation:** Implemented: `web/src/engine/speakerAdapter.ts` implements the `Speaker` that `web/src/devices/usePlaybackDevice.ts` drives, on the existing lease, heartbeat and reconnect, including volume routing. CI verification remains pending. **Independently Verified:** No.
6. **BF-0457-06 - Offline render and export.** **Acceptance:** Chunked offline render with cancel; WAV export always; FLAC via WASM encoder with checksum and duration validation; explicit download action; failures never present a partial file as complete; behind `cloud.local_export`. **Required verification:** Vitest, Playwright export specs including a long synthetic mix. **Implementation:** Chunked, checked render and export (`web/src/engine/render.ts`, `export.ts`, `wav.ts`, `flac.ts`, `flacDecode.ts`) write WAV and FLAC; FLAC is the TypeScript encoder described above, verified by a full decode with CRC and MD5 checks, not a WASM encoder. The member-facing surface is the shared Save as an audio file panel and the export list (`views/ExportPanel.tsx`, `ExportJobs.tsx`), answered on the device by `web/src/cloud/localExport.ts` behind `cloud.local_export` (T-20261126-96d3): the export writes the same transitions playback plays (clips made ahead, kept on the device or made first with the seam maker, joined by `renderedSeam.ts`'s arithmetic, each song at its playing level), cancellable at every step, and the finished FLAC is a link in the tab's memory that the member's own press saves. The long-mix Playwright export spec is pending. **Independently Verified:** No.
7. **BF-0457-07 - No-egress proof for the engine.** **Acceptance:** An authenticated network capture during import, play, mix and export on a local-first account shows zero audio bytes leaving the device; the capture procedure is scripted and repeatable. **Required verification:** The ADR-0466 egress gate. **Implementation:** In progress: the capture procedure exists (`tools/bf_egress_capture.py`, `tests/test_bf_no_audio_egress.py`). Authenticated captures during import, play, mix and export remain pending under the ADR-0466 egress gate. **Independently Verified:** No.
8. **BF-0457-08 - Reference parity harness.** **Acceptance:** The engine renders the ADR-0459 golden set and the comparison harness (synthetic owned audio, LUFS, true peak, seam timing) runs in CI on all three browser engines. **Required verification:** CI runs with recorded numbers, not mocks. **Implementation:** In progress: `web/src/dsp/golden/goldenSet.test.ts` contains golden comparisons for LUFS, true peak and seam timing with the Python engine. Three-browser CI runs with recorded numbers remain pending. **Independently Verified:** No.

## Governance

Accepted by the owner on 2026-11-17. The runtime makes no venue or device claim by itself: every public capability statement routes through ADR-0460 qualification and ADR-0466 gates. The standalone local engine remains the musical reference and is unchanged.
