# Staging walkthrough notes

Things to refine, found by walking staging (app.staging.selectadj.app) as the owner's accounts. Each item says what was seen, where, and what good looks like. Newest first. Owner of each fix in brackets.

## 2026-11-24 evening: admin console, hosted storage

### Hosted storage (tochimba26 after the console switch)
1. **Upload fails with the wrong words.** Add music, one 3.4 MB MP3: the API answered 503 and the page said "SelectaDJ is being updated and is back in a moment. Anything playing keeps playing." The server log says `Couldn't start upload ...: NoSuchBucket`: the staging R2 bucket does not exist. A storage misconfiguration must never read as an update. Good: "We couldn't store this file right now. Nothing was lost. Try again later, or contact support with reference R-..." and an operator alert. [audit] **Fixed (audit, 712d24f1):** 503 `storage_unavailable` with "We couldn't store this file right now. Nothing was lost. ... reference R-...", the reference in the log, and a `storage.unavailable` operator alert at most once in ten minutes per error code.
2. **The failed upload lingers as "Unfinished uploads ... 1 part"** with "Choose the same file again and SelectaDJ carries on". That is wrong when the cause is on our side. Good: say it failed on our side, offer Remove, and retry by itself when storage is healthy. [audit] **Fixed (audit, 712d24f1):** an upload storage never started reads "That was on our side, and nothing was lost", has Remove, and is checked again every 30 s; once storage takes it the page says to choose the file again to finish.
3. **"Nothing has changed for you" note shown to an account that was just switched to hosted mode.** It is the note for older hosted accounts ("Your hosted library ... work exactly as they did"). Good: a newly granted account sees "Cloud storage is on for your account. Upload songs in Add music; they're stored privately and mixes can be rendered for you." once. [audit] **Fixed (audit, b5f96baa):** an account with nothing stored when it first sees the note gets "Cloud storage is on for your account"; the choice is kept so an upload never swaps it.
4. **The Library mixes both modes without explaining.** After the switch, Library still leads with "Connect music" and "2,918 of 2,919 songs can play here. Choose your music folder", next to a new "Add music" upload page. Good: one clear explanation of where this account's songs live (on this device, in Cloud storage, or both) and which button does what. [audit + editor] **Fixed (audit part, 1e83634e):** an account with Cloud storage reads, at the top of Library, where its songs live and that Connect music adds songs from this device while Add music uploads them to Cloud storage.
5. **The Library took about 30 seconds to open** (2,919 songs) and showed "This is taking longer than expected. You can keep waiting." Good: first rows within a second (paged, or from the offline catalogue), the rest streaming in. [audit] **Partly fixed (audit, 1e83634e, db75d1c9):** the catalogue is read 1,000 songs a page, not 100, and the first Library of a visit opens from this browser's last copy while the server's list arrives. Not yet measured on staging (to-do T-20261124-c68a).

### Hosted storage after the buckets were created (same evening)
12. **Upload now works end to end to storage.** After creating the four EU buckets and their app-origin CORS rule, the same MP3 said "Upload accepted" and the object is in `selecta-staging-originals` under the account's own `w/{workspace}/a/` prefix.
13. **The uploaded song is nowhere in the app.** Library still says 2,919 songs and lists only the folder songs; there is no hosted section, no "In Cloud storage" filter and no processing state for the upload. Good: a hosted upload appears in Library at once with "Preparing" then "Ready", marked as stored in Cloud, playable on any device. [audit] **Fixed (audit, bb0e6135):** an accepted upload joins the catalogue by its content hash (title and artist from "Artist - Title" file names; a song already imported keeps its tags), so Library lists it, marks it as stored in Cloud and plays it from the stored copy; the page reads the hosted copies again after an upload.
14. **Nothing processes it on staging.** Workers (Modal) report nothing, so analysis and server rendering cannot run. The app must say so honestly ("Your song is stored. Preparing it for mixes is waiting.") and the console must show the waiting job. [audit + admin]
15. **Library counts jump while it settles.** "2,918 of 2,919 can play here" became "2,405 of 2,919" and "513 songs need your permission again" seconds later, with no explanation of what changed. [audit] **Fixed (audit, 1e83634e):** when fewer songs can play after checking, the banner says how many chosen here before need this browser's permission again, and why.
16. **Artist parsing from file names.** "Adekunle Gold - Call on Me.mp3" shows title "Adekunle Gold - Call on Me" and artist "Unknown Artist"; an "Artist - Title" file name should be split when tags are missing. [fingerprint/import owner]
