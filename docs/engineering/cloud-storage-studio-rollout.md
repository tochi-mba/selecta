# Cloud storage and shared Studio rollout

Cloud keeps two workspace modes. On this device performs every audio operation locally and sends only permitted song facts, recipes and control data. Cloud storage uses verified hosted originals, analysis and rendering. Connect music routes to the active mode. Storage and speaker ownership are independent.

- [ ] Fix Library Start a mix and automatic Studio builds. Pick and order from the full eligible catalogue with pinned endpoints and musical steering. Preserve current playback on a failure. Cover the alphabetical shortlist regression.
- [ ] Use the shared Studio for suggestions, shaping, drafts, editing, preview and export. Integrate uploads into Library and redirect Add music links.
- [ ] Persist a workspace mode and revision. Resume approved device-to-cloud transfers and cloud-to-device restores, verify originals and preserve song identity. Fence stale work. Prove zero audio upload in On this device.
- [ ] Reuse versioned deterministic analysis after exact file verification. Confirm decoded equivalence before expanding to retagged files.
- [ ] Match local planning and rendering context. Use a resolved render specification for cache lookups after candidate selection. Require verified access to both originals for hosted cross-workspace clip reuse and prove that cache availability leaves planning decisions invariant.
- [ ] Preserve saved arrangements and rendered versions. Show a listen-through notice when a rerender may sound different. Verify playback and export integrity, permissions, interruptions and multi-device behaviour.

ADR-0455, ADR-0456, ADR-0465, ADR-0469, ADR-0479 and ADR-0489 describe the existing boundaries. Update the affected decisions alongside implementation.
