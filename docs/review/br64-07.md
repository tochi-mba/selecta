## What this branch actually implements

- Opt-in `local_first.personal` Cloud Home gives **Play Here**, **Control Another Device**, and **Edit Without Music** journeys and intent-preserving links (`/listen?mode=play|remote|edit`).
- The current regression hiding all persistent audio status and hiding the old Listen/Studio behind an engine-install link is corrected. Browser-first accounts mount **BrowserPlaybackDock** in all authenticated shell destinations and **BrowserStudio** for the Studio destination. The legacy `CloudTransportDock`, `CloudListen` and v1 `MakeCloudMix` remain unchanged **when local_first.personal is off**; they must not be mounted under browser-first Cloud because they depend on historical hosted-audio routes. No Cloud media URLs are requested by BrowserStudio.
- Added browser-first aliases `/studio`, `/mixes`, `/player`, `/discover` preserving the existing canonical `/listen`; `?mix=opaque_id` opens an exact saved recipe. Feature-aware navigation, auth, suspended/error states, settings, billing, Rooms, staff admin and existing Library/Uploads remain mounted by the original shell. The latter two are owned by Agent 02 and may need independent UX updates.
- `BrowserStudio` uses **real** metadata-only schema-v2 `/api/cloud-mixes` HTTP endpoints already implemented by LF04. It reads history and exact occurrence IDs without downloading files; can reorder, edit cues, select seam intentions and durations, undo/redo, keep a session-local unsaved draft, restore earlier revisions as *new revisions*, and safely refuse 409 stale edits. Saved revisions are immutable at the backend.
- Local file selection is user-initiated and routed ONLY to an injected browser media port. This page never reads uploaded media bytes and never forwards a `File`, path or Blob to the Cloud API. A newly indexed exact canonical reference is saved as metadata; no title-only replacement. Source permission, alternative master, unsupported processing and stale cache states remain distinct.
- Capability/readiness is revision-, device-, occurrence-, canonical track- and recording-version-fenced. A valid fresh 5/8 availability report shows **5 of 8**, not playable/renderable. An edit invalidates saved-revision readiness. Only a fresh 8/8 exact match can enable local render; Play Here additionally requires verified output. There is no mobile form-factor exclusion: a supported phone with a real renderer and permitted local files can access render.
- Optional typed ports for BrowserMedia (`importFiles`, `inspect`), BrowserPlayback (`playHere`, `previewTransition`, `controlAnotherDevice`, truthful status) and BrowserRender (`supported`, `prepare`, `render`) live in `lf-mix-repair/browserPorts.ts`. `CloudRoot` accepts an optional `browserPorts` prop or integration code may call `registerBrowserStudioPorts`. No built-in dummy audio engine or network-upload fallback is permitted.
- Responsive list/timeline, touch-friendly move controls, keyboard/button alternatives, labelled cue/seam inputs, visible undo/redo and explicit unsupported/unknown states. Rendered output is exposed through a separate **Download local export** tap, accommodating iOS/Safari user activation requirements. The blob remains in this browser until downloaded; no media is uploaded. Media evidence is never persisted in sessionStorage; only metadata edits are.

## Known blockers / safety limits

- **No complete browser playback, media indexing or rendering implementation is claimed in this PR.** Runtime ports intentionally default to absent, with editing enabled and action buttons disabled. External agents must register adapters before a real Play Here or Render Here action works.
- Live user-agent/device memory, battery, thermal, Bluetooth, screen lock, actual sound checks, OS file-permission eviction, offline browser termination, Playwright hardware matrix and a physical phone render remain to be verified after cross-agent integration. The synthetic fixture is not evidence of audible playback or codec-quality parity.
- Historical advanced Studio feature parity (waveform, stems, musical analysis and full timeline manipulation) requires Agent 01/03/04/05 browser ports and coordinated view migration. This branch preserves their old files and controls in standalone mode rather than substituting a toy reimplementation.
- Current backend `/api/cloud-mixes` may be gated by `cloud.mix_create`; integrator must align the browser-first account feature flag and API route availability. No global flags or `api_cloud.py` changes belong here.
- The repository could not be cloned or local tests run in this session because this runtime could not resolve `github.com`. Commits were created on a GitHub branch from the exact required SHA using the connected GitHub API. GitHub Actions results (if triggered) are the available remote validation evidence and must not be misrepresented as local test success.

## Zero-cloud-audio boundary

Only `GET /api/cloud-mixes?schema_version=2`, `GET /api/cloud-mixes/:id?schema_version=2` and metadata-only `POST /api/cloud-mixes` or `POST /api/cloud-mixes/:id/revisions` are issued by this Studio. The source import, device inspection, playback, seam preview and render are injected local browser ports. No source path, media blob, PCM, stem, waveform, fingerprint or export file is sent in any Cloud request. Renderer admission requires authenticated local source evidence; no inferred title match or fallback to server processing is allowed.

## Integration update on PR #64 — shared local/Cloud UX (2026-11-14)

This review began on the isolated Agent 07 branch and now describes the
**integrated** code on the sole open PR #64 branch. The earlier agent-specific
contracts and audit notes above are historical; use the following current
implementation status for review:

- `CloudPersonalNavigation.tsx` imports the same `DESTINATIONS` metadata as
  the local `Shell` and uses native anchors instead of non-link navigation
  buttons. Browser Back/Forward, copy link, open in new tab, current-page
  semantics and deep links remain normal browser behavior.
- `/listen` is now a distinct shared-browser-engine and locally-authorised
  library experience (`BrowserListening.tsx`), while `/mixes`,
  `/mixes/mine` and `/studio` have distinct page titles and focused
  Studio entry surfaces; they share one portable recipe and media adapter.
- `/workshop`, `/devices` and `/rooms` expose Workspace/device/Rooms
  journeys without mounting the hosted audio transport. Cloud-only billing,
  account data export, Lucy settings, subscription consent, staff admin
  and legacy account migration remain accessible.
- Responsive shell parity: persistent player, local icons, desktop rail,
  accessible mobile four-item bottom music navigation plus More, touch targets,
  forced-colors and reduced-motion fallbacks.
- The new `local_first.personal` release flag is registered safely with
  production default false. `dev.cmd cloud` explicitly enables it by default
  for development, unless `SELECTA_FLAGS=-local_first.personal` is supplied.
- Metadata/readiness integration uses browser IndexedDB and local file handles
  only. Do not confuse the separate dev loopback `local-watches.sqlite`
  with standalone `songs` or the browser's local index; none gives the
  other automatic music playback permission.

The detailed status/gap/acceptance table is maintained in
`docs/browser-cloud/parity.md`. The local advanced mixer, song inspector,
native study/backup, Lucy AI, stem waveforms and native DSP are **not** thereby
certified for browser Cloud. Real hardware, screen reader, security and
cross-device tests remain release gates. The Python/native standalone app
was not replaced or altered by this UX integration.
