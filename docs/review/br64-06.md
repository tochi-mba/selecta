## Summary and trust model

This branch adds a browser-native **Cloud control-plane bridge**, not a Python
audio daemon. iPad, Android tablet and phone browsers may be speaker executors
after live source/output/capability preflight; other devices can remotely control
them without possessing or accessing their files.

- The Cloud API handles account-scoped device/session metadata, source-ready
  counts, command queues, auditable state, speaker selection and multi-step
  takeovers. It does **not** process or store user audio, PCM, stems, raw paths,
  upload URLs or file handles.
- The verifier for the HUMAN access token is supplied by the existing Cloud
  integration as a FastAPI dependency. It MUST return a trusted
  \`ActorScope(actor_id, workspace_id, role, zones)\` obtained from authenticated
  account/workspace/zone membership and entitlements. **Never** derive this
  from client-supplied headers/body, a local profile, or any bearer token that
  has not been verified by the configured issuer/audience/expiry.
- A browser session has an opaque 48-byte URL-safe token issued on registration,
  stored server-side as a SHA-256 digest, bound to its human actor and workspace,
  and rotated on refresh. Clients send it only in
  \`X-Selecta-Session-Token\` over HTTPS alongside the independently verified
  user bearer token. Device session tokens never appear in discovery responses.
- The server derives a session-specific HMAC-SHA256 key from a **persistent
  server-only 32+ byte secret**, the session ID and token digest. Signed command
  envelopes are verified in the browser with WebCrypto before execution.
  Rotation invalidates prior command signatures. HMAC is defense in depth;
  HTTPS plus account/session authorization remains mandatory. Never log keys.
- Cross-account and cross-zone resource reads/writes fail closed. Owners/admins
  can revoke sessions; sessions can revoke themselves with their current token.
  A revoked active speaker is shown as **unknown**, never automatically silent.
- Cloud never sends a remote controller source paths, local file handles,
  source hashes, stems, waveform samples, PCM, audio bytes or reconstructible
  diagnostics. Presence includes only booleans, counts, versions, timestamps
  and output state. User-controlled command argument schemas are closed.

## HTTP contract (schema_version=1)

Routes are mounted under \`/api/lf/v1\`; POST bodies are strict JSON, unknown
fields forbidden, and every response uses \`Cache-Control: no-store\` through
the identity dependency. Responses and commands use UNIX epoch seconds
(not ISO strings). Every device session API also requires
\`X-Selecta-Session-Token\`.

| Method | Route | Purpose |
|---|---|---|
| POST | /devices | Register browser device/session, return session ID/token/HMAC key privately |
| POST | /devices/{device}/revoke | Owner/admin revoke all device sessions |
| GET | /zones/{zone}/devices | Scoped, redacted device discovery and live capabilities |
| GET | /zones/{zone}/speaker | Actual selected speaker, ownership generation, unknown if stale |
| POST | /sessions/{id}/refresh | Rotate session token + command HMAC key |
| POST | /sessions/{id}/presence | Foreground/runtime, source-readiness, output and fence observations |
| POST | /sessions/{id}/revoke | Revoke own session or privileged owner/admin revoke |
| GET | /sessions/{id}/recovery | Metadata-only pending/uncertain operations; never auto-replay |
| POST | /zones/{zone}/commands | Authenticated role-scoped command queue |
| POST | /zones/{zone}/takeovers | Begin safe, generation-fenced multi-step handoff |
| GET | /sessions/{id}/commands/next | Authenticated browser pull, signed command or null |
| POST | /sessions/{id}/commands/{op}/ack | Executor accepted/applied/rejected/conflicted with evidence |
| GET | /zones/{zone}/commands/{op} | Truthful command lifecycle and expiry |
| GET | /zones/{zone}/takeovers/{id} | Transfer stage, never speculative success |

A client sends an explicit command body such as:

\`\`\`json
{
  "target_session_id":"ipad_session",
  "operation_id":"pause_123",
  "idempotency_key":"request_123",
  "action":"pause",
  "arguments":{},
  "expected_generation":1,
  "recipe_revision":null,
  "policy_version":1
}
\`\`\`

Cloud synthesizes the signed envelope from its verified actor, not the request.
The exact canonical fields are: \`schema_version, operation_id, actor_id,
actor_role, workspace_id, zone_id, session_id, target_device_id,
expected_generation, expected_recipe_revision, policy_version, sequence, action,
arguments, created_at, expires_at, idempotency_key\`. All are present,
snake_case, type-checked, with closed action-specific arguments. This is the
browser protocol's explicit version-1 wire contract, independent of older
\`actor:{kind,id}\`, ISO time and \`takeover/change_output\` UI dialects.
Legacy Python \`CommandEnvelope\` remains for native standalone; the new
TypeScript client never emits incompatible legacy payloads. Browser handoff
steps are \`prepare_output, release_output, activate_output\` and are
**server-only** commands, never publicly queueable transport actions.

## Command lifecycle and ownership

\`created -> authorised -> queued -> delivered -> accepted -> applied ->
acknowledged\` is recorded in SQL. Terminal states are \`rejected,
conflicted, superseded, expired\`; an ACK cannot jump from delivered directly
to applied. Accepted/delivered is never proof of execution. On successful
local proof, applied and acknowledged are persisted sequentially. A lost HTTP
response on an already delivered ephemeral command does NOT trigger a second
Play/Skip. The UI can query its operation status; expired means **not
confirmed**, not "definitely never ran."

A takeover reserves the zone and its next generation transactionally:

1. **Prepare target:** must have recent foreground running browser,
   AudioWorklet capability, permitted local sources, fresh local source
   check and a recent locally silent output check. The target confirms
   preparation and a durable local fence via ACK.
2. **Release previous:** if an owner exists, it must still be reachable;
   Cloud sends a release command. The old browser must independently stop
   its audio, confirm physical silence and persist the new fence before
   reporting completion. Cloud must not equate heartbeat timeout or HTTP
   delivery with old output silence. If source is gone or partitioned,
   do not issue activation.
3. **Activate target:** Cloud records the released zone as silent, then
   sends activation. Only an explicit confirmed audible output/sound-check
   and correct generation ACK commits the new owner. Failed/missing ACK
   leaves owner silent or unknown, not falsely playing.

For a brand-new, empty zone, an owner/admin must make an explicit **on-site
physical silence assertion**, rather than inferring silence from absent DB
state. Transfer progress is scoped, idempotent and generation-fenced. A
second concurrent takeover returns \`transfer_busy\`. Device discovery
and browser claims do not establish *cryptographic proof of physical audio*:
the browser must rely on a genuine human sound check or trusted output
monitor; the UI must display this limitation.

## Browser/mobile runtime and offline semantics

Only an awake, active, foreground browser is marked reachable (heartbeat
age <=20 s). Output/source preflight expires after 15 s; a stale/suspended/
closed browser may still be audibly playing, so owner state becomes unknown
rather than silent. HTML document closure is not guaranteed to send revoke.
Polling uses same-origin HTTPS, human bearer auth, session token and
WebCrypto verification, not WebSocket listeners or local media HTTP services.

While executing offline, Agent 01/08 may continue using a locally
authorised cached schedule and local files, with a locally durable fence.
Cloud cannot reach an offline/suspended browser or guarantee queued remote
commands execute. On reconnect, reconcile command status and operator
evidence; never blindly replay an ephemeral Play/Skip. HMAC token material
is memory-only in the sample client, so a full reload needs a new session
or a deliberately reviewed secure recovery flow; old audible ownership
remains unknown until resolved.

## Failure semantics and security tests

- 403: invalid/revoked human session or device session, insufficient role,
  cross-workspace access, first-owner physical-silence proof missing.
- 404: unknown operation/session/transfer (never leaks another workspace's
  details).
- 409: stale generation/revision/policy, unavailable speaker, stale source,
  unverified output, unsafe network partition, concurrent transfer,
  missing physical proof, late/contradictory ACK.
- 422: unsupported protocol/action, malformed identifiers and arguments,
  unknown request fields, paths, audio payloads, bad evidence formats.
- 413: oversized declared Content-Length; trusted ingress additionally
  enforces streaming body limits.

Test fixture uses deterministic fake browser HTTP, no actual user audio or
filesystem handles. Regression suite covers tablet registration, staff phone
control, cross-account scope, duplicate/stale commands, network loss,
missing media, manual initial claim, token rotation/revocation, release
silence/fencing, missed acknowledgements and concurrent handoffs.

**Not yet verified by this branch:** PostgreSQL production migration,
real iPadOS/Android audio/sound check, hardware output isolation, end-to-end
browser DSP execution or complete native-cloud protocol migration.
Do not merge until the integration and device acceptance gates pass.
