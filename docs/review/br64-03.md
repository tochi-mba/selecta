# BR64-03 — Browser DSP integration and native parity ledger

**Source branch** `feat/br64-03-browser-dsp` at required fork `0c7d321d9005c507ba7adde30b15e70289e357b3`. **Target** `docs/local-first-cloud-rearchitecture-20261113`. Controlling ADR-0485 from merged PR #84; that architecture is newer than the exact initial fork but its browser-first boundaries are respected.

## Scope and safety
Implemented self-contained TypeScript under `web/src/dsp/{core,analysis,transitions,time-stretch,effects,workers,fixtures}`. No edits to Python, AudioWorklet, Cloud, neural model, encoder, integration package manifests or native playback. Original standalone algorithms remain untouched. Input is **already decoded, locally authorised planar PCM**. DSP never fetches audio, invokes a remote processing API, includes file handles in telemetry or uploads audio. Invoke `runDSPJob` in a dedicated Web Worker, not directly from the UI event loop or AudioWorklet render callback.

**Important:** This is a **functional browser DSP foundation**, not a completed/native-equivalent port or proof of mobile device support. The pure TypeScript modules have no external Python native dependencies. Music-specific quality must be validated on licensed/golden real audio in separate native comparison and listening campaigns before claiming parity.

## Contracts for integration
- **Agent 01 (audio engine):** import `web/src/dsp/core/index.ts` or `web/src/dsp/workers/client.ts`; `PreparedAudio.pcm` is planar `Float32Array[]` at declared `sampleRate` (default native 44,100 Hz), `originSeconds` and `startSeconds`; schedule only prepared PCM in the real-time engine, never run FFT/render inside `AudioWorklet.process`. Workers send typed buffers with transfer ownership. Playback eligibility requires local source verification, audible-output test and device-specific calibration.
- **Agent 02 (local media):** provide decoded `PCM={sampleRate,originSeconds,channels}` with all channels same length, nonzero frames, local authorised sources. Device name/OS is not an admission criterion. Source time must cover any warp and filter/tail halo.
- **Agent 04 (neural):** implement `BeatModelAdapter.infer(pcm)` and `LearnedKeyAdapter.infer(chroma)`; do not misreport approximate browser beat confidence as learned output.
- **Agent 05 (render/export):** call `runDSPJob({kind:'render',id,script,sources,windowStart,duration,budget})`; use separate bounded windows, overlap-add/halo, persistent local checkpoints and verified local codecs. `renderTransitionWindow` returns PCM and peak reports, **not** an export file. Use external cancellation to terminate the dedicated Worker.
- **Caller budgets:** `MOBILE_BUDGET` max 384k frames, stereo, 32 MiB per requested PCM buffer; `DESKTOP_BUDGET` max 1.152M frames, stereo, 128 MiB per buffer; quality/runtime not hardware-certified. Callers must measure total working-set memory (filter banks, FFT, worker structured clones, browser audio buffers), constrain concurrency to one on low-memory phones, and adapt if memory allocation/thermal pressure occurs. No guaranteed global process memory cap.
- **Errors and provenance:** `DSPUnsupported.code='unsupported_here'`; `DSPCancelled.code='cancelled'`; nullable beat grid and unknown key; `version='br64-03/1.0.0'`; prepared artifact quality always `approximate`.

## Verification matrix and outstanding gates
Synthetic fixtures in `fixtures/synthetic.ts` intentionally cover two-tone, 120 BPM clicks, silent PCM and equal-power seam. Unit tests target FFT inversion, resampling count, K-weighted loudness/silence gating, key/Camelot, non-neural BPM, stable raw grid, filter reconstruction, limiter, time-stretch pitch and duration, cancellation, memory/window rejection and prepared artifact. Playwright spec `web/e2e/br64-03-dsp.spec.ts` validates deterministic render/sample count under its runner. **Tests are synthetic; no true native comparison master files have been captured.**

To run:
```sh
cd web
pnpm install --frozen-lockfile
pnpm exec vitest run src/dsp
pnpm exec tsc --noEmit
pnpm exec playwright test e2e/br64-03-dsp.spec.ts
pnpm build
```

Still required before marking full parity: capture source-licensed golden native/reference output per style; compare sample timing (<10ms beat pocket target from native tests), true peak ≤-0.9 dBTP, BS.1770 LUFS, bass-owner spectral separation, stereo phase, phase-vocoder transient smearing, real listening evaluation, UI-not-blocked test, worker termination and egress test, 6h powered iPad/Android foreground venue runs, Android/iOS thermal/RAM/Safari PWA and microphone/speaker route interruptions. Neither native parity nor real-device acceptance is claimed by this agent.

## Recipe builders added
`makeTransition(style, a, b, exitCue, entryCue, options)` uses precomputed BPM, bar/grid confidence, energy and low-frequency share metadata; creates native-inspired curves and bar-quantised bass swaps. It rejects unsupported beatmatched pairings and missing verified lyric word-end timing. The `tempo_ramp` metadata identifies a *required* beat-pinned warp; it does **not** constitute equivalent dynamic tempo-ramp audio yet. All cue times must be supplied by an authorised analysis/cue-selection pipeline, not invented by the browser. The builders are deterministic helpers, not full parity with `selecta.styles`.

### Loudness contract
`integratedLoudness(pcm)` calculates gated, K-weighted LUFS (mono/stereo only, minimum 400ms) while `rmsDb` remains explicitly *unweighted*. The prepared artifact now exposes `integratedLufs: number | null`; null for too-short windows and silence. This is an approximate BS.1770 port until paired measurements against native `pyloudnorm` become available; it does not establish reference-grade loudness or output safety for venue hardware.

## Conservative scratch-memory admission and context
Before rendering, the browser layer estimates a high-water scratch footprint from concurrent PCM, resampling, filter bank, tails, stretch and limiter buffers; it returns `unsupported_here` and requests a smaller window if the device budget is exceeded. This is a *conservative estimate*, not a browser process-wide heap guarantee. Tempo-ramp recipes with `needsBeatPinnedWarp` explicitly reject until the dynamic beat-point warp is implemented and verified, rather than silently pretending the constant-ratio script is equivalent. Nonzero PCM source origins now shift onset-grid lookup correctly.
