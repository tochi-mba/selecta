# BR64-08 — Browser-native venue, business and Rooms recovery handoff

**Base:** `0c7d321d9005c507ba7adde30b15e70289e357b3`, integration target
`docs/local-first-cloud-rearchitecture-20261113`. **Authority:** PR #84,
ADR-0485, browser device matrix and browser-first master plan.

## Implemented in this branch

- `web/src/venue-player/browserAudio.ts` is a real Web Audio *local executor*:
  authorised user-granted `File` bytes are decoded in the browser, played by an
  `AudioBufferSourceNode` to the default OS route, and transitioned with a bounded
  0–10 second two-deck crossfade. Local preview supports pause, resume, safe gain,
  manual next, 440 Hz 0.5-second sound test, and on-site acknowledgement.
- Never uploads, serialises or sends selected media to Cloud. Import requires an
  exact local File and explicit authorisation. No URL/remote source path is accepted.
  Decode is bounded to 150 MiB per file and three prepared AudioBuffers.
- `web/src/venue-player/programme.ts` is a small foreground-only programme runner using the typed Cloud/session, exact-local-media and policy adapters. It fences the speaker session, keeps committed/prepared/planned/fallback identities separate, preflights the near-term next recording and crossfades when the local audio clock approaches a transition. It fails closed on expired rights, closed hours, lost foreground and ended playback; offline reporting failure does not stop already-granted local audio. **This runner is not wired to real Cloud sessions yet and its UI-loop timer is not production-grade DSP scheduling.**
- `web/src/venue-player/policy.ts` evaluates business opening windows and
  overnight windows in the venue's IANA timezone, including repeated/missing DST
  hours; no implicit clean/explicit permissions. It offers a separate allowlisted
  guest catalogue projection.
- `web/src/business/localFirst/BrowserVenueSetup.tsx` is wired into onboarding
  and the Venue Devices tab. The actual tablet plays the file; no extra computer,
  installed Python service, localhost engine or second device is involved in
  **this on-device sound check**. Explicit rights/content review gates local
  playback. A role gate stops viewer/read-only users from starting this UI.
- HQ readiness now recognises a browser device and reports foreground,
  interruption, source permission and low-battery warnings when provided by its
  source. Existing server-side reports remain the authority for HQ.
- `web/src/kiosk/audio.ts` exposes `browserKioskAudio` over the real executor;
  legacy `stubAudio` remains for older screen tests and must not be used in
  production. Screen truth still requires `playingConfirmed`.
- `src/selecta/lf_venue/browser_session.py` validates strict scoped, fenced,
  allowlisted browser health reports. Stale, hidden, interrupted and unchecked
  sessions are not claimed as audible. Its `operator_checked` evidence is **not**
  an instrumented physical output meter.
- Rooms retain the existing local-first bridge, strict speaker freshness,
  request stages, request-scope checks and privacy projection. Added explicit
  negative tests for unverified guest catalogue entries, stale speakers,
  forged receipts and cross-zone progress.

## Browser and physical limitations

- One OS-selected physical output per tablet. `AudioContext.setSinkId`,
  speaker-independent zones, Sonos and Chromecast are **not assumed**.
- An unlocked/running AudioContext is **not** a physical speaker probe. The
  “I heard it” control records operator testimony for this browser session.
  Output changes, song transitions and interruptions invalidate the evidence.
- Screen Wake Lock is best-effort, and Guided Access or a Home Screen web app
  does not guarantee continuity. Browser hidden/frozen/discarded, Android Doze,
  Bluetooth/output changes, iPad suspension, screen lock and reboot require
  explicit human recovery. No autonomous restart is promised.
- Internet loss while this page remains executing can preserve already decoded
  music only. Cross-device control, new Rooms requests, remote staff actions,
  auth refresh, neural jobs and other Cloud services are unavailable offline.
- Browser support: actual media decoding, autoplay unlock, output route and
  memory on Safari/iPadOS, Chrome/Android, Samsung Internet and other browsers
  require real version/device evidence. The mere user-agent string is not a
  capability proof.
- Privacy/licensing: no Spotify/Apple Music or DRM stream is imported; users
  must hold necessary venue public-performance and recording/derivative rights.
  The checklist is not a licence determination. No original media is hosted.

## UI parity and accessibility

Manager: venue/zone selection, local file import, rights review, tap-to-start,
speaker test/acknowledgement, local manual next/pause/resume/stop, safe gain,
freshness and interruption warnings. Existing fleet 1–20+ views, schedules,
licensing, staff controls and Rooms are preserved. Large touch actions, mobile
wrap, tablet landscape, keyboard controls, accessible labels/live errors and
reduced-motion CSS are added. VoiceOver/TalkBack **manual testing outstanding**.

**Hardware release blockers:** powered six-hour iPad Safari Home Screen and
Android Chrome/Samsung Internet playback soaks; local-file permission revocation;
screen lock/Doze/tab discard/reboot failure; actual USB/Bluetooth/AirPlay output
verification; concurrent remote staff and QR requests; DST/overnight live
schedule; battery and speaker-disconnect fault tests; tenant/rights audit;
fallback quality/transition listening; memory/thermal measurements; accessible
VoiceOver/TalkBack/400% zoom audits.

**Overall:** this PR introduces a genuine, no-install, device-local browser
audio path and business setup surface, not complete production-certified
cross-device venue service. Keep unverified gates visible and do not merge until
the integration owner accepts the remaining work.
