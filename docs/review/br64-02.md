# BR64-02 — Browser-local music and device capability system

## Baseline and responsibility

Started from commit 0c7d321d9005c507ba7adde30b15e70289e357b3 on isolated branch feat/br64-02-local-media, with PR #84 / ADR-0485 governing architecture. All changed files are assigned to Agent 02; no edits to the legacy standalone library, main, PR #64, API mounting, player, or other agents' directories.

## Delivered

- The browser local catalogue (web/src/media) separates opaque local recording identities from canonical Cloud track IDs. It supports multiple selected files, directory picker handles where available, directory-input fallback, drag/drop, filename and duration metadata, cancellable/cooperatively yielding scans, exact hashes of bounded-size files, distinct versions and changed-content detection. Ready, Candidate, Missing, Version Mismatch, Permission Required, Unsupported Codec, Source Disconnected and Unknown are distinct.
- Runtime profile (web/src/device-capabilities) probes Web Audio, AudioWorklet, SIMD, workers, quota, output selection, wake lock and WebGPU visibility. Results use available, degraded, unsupported_here and unverified with reasons, plus a synthetic worker probe with a wall-clock cutoff. Hardware inference remains device- and model-specific.
- In local-first mode, /uploads and /library show browser-native Connect Music and local Library. Non-local-first legacy routes remain intact. Browser UI never sends audio or local hashes to Cloud and never deletes files when forgetting a source.
- Python browser_contract.py permits only aggregate device readiness counts and explicit browser activity; it rejects unverifiable claims of physical speaker output.

## Agent contracts

**Agent 01, real-time audio:** Obtain File from localCatalogue(workspaceId).openRecording(localRecordingId), or a Blob from openBlob(localRecordingId), on the speaker browser only. Those functions may throw if the content changed or access expired. Never fall back to Cloud file proxy. A verified canonical ID is not a playable recording reference. The local preview is not the complete DSP audio engine.

**Agent 03, DSP:** Use the same browser-local Blob/File interface. Run actual format validation, decoding and chunked algorithms in workers/WASM on this device. Distinguish local content SHA-256 from Cloud canonical ID; never assume title matches imply same edit/master. The existing browser preview does not qualify DSP parity.

**Agent 06, cloud controller:** Consume only availabilitySummary(records, running) and the strict BrowserAvailabilitySummary.parse() allowlisted wire schema. No file names, paths, handles, fingerprints, media bytes or private recording IDs are transported. Actual per-track readiness requires target-device resolution using resolveRecording with verified local identities. Generation fencing, authenticated device sessions and scope checks remain Agent 06 integration work.

## Remaining limitations and hardware gates

- Browser media bindings are currently in-memory: after reload the user needs to re-select source files. No persistent folder watch or arbitrary storage permission is claimed.
- Exact SHA-256 currently checks complete files at most 32 MiB; larger source identity remains unverified rather than making a false exact match. Streaming digest and durable permission-aware indexes are still required.
- HTML media metadata success does not prove the physical speaker is audible or that DSP can decode every frame. A manual sound check is required.
- Safari iOS/iPadOS may require Files re-selection; system output selection, foreground behavior, PWA sleep, storage eviction and real WebGPU models must be tested on physical hardware.
- No claim of native apps, Spotify/Apple Music DRM access, unattended iPad service, restart autopilot, auto-multi-zone, or completed heavy ML port.
- Real device matrix: iPhone Safari/PWA, iPad Safari/PWA, Android Chrome, Samsung Internet, Firefox Android, desktop Chrome/Edge/Firefox/Safari, Chromebook, SD/USB document providers and speaker/BT interruptions are **outstanding**.
- Playwright file name is br64-02-file-picker.spec.ts. The existing root web/playwright.config.ts discovers only *.e2e.ts; Agent 10 must include this spec explicitly.
- cloudCatalogue.ts remains historical hosted-audio code. Agent 01 and final integration must cut it over in local-first mode; do not route it to a Cloud music proxy.
