## Security model

1. Cloud upload, old media URL and proxy routes deny both stale GET and POST requests. A server-side exception flag or legacy subscription does not reopen them; Cloud `SELECTA_MODE=cloud` always resolves `Phase.SEALED`. R2 reads/signing in hosted mode are denied one layer deeper.
2. `admit_cloud_metadata(body, content_type, workspace_id, kind)` enforces UTF-8 JSON, exact versioned typed allowlists, tenant equality, bounded payloads, duplicate JSON key rejection, binary/magic/encoded-media inspection, path/token/url/fingerprint redaction and safe refusal codes. **It is a reusable guard, not yet a universal app middleware.** The integration owner must mount it across Cloud metadata and approved AI ingress, and must prevent raw untrusted body logging before that validation.
3. Account ZIP never includes original media, derived audio, stems, uploads, presigned URLs, source paths, raw asset SHA or raw revision provenance. Historical recipe objects retain only allowed nonreconstructible fields and are marked for review if the source contract is invalid.
4. Workspace-scoped SQL queries, role checks and deletion tombstones remain. Never traverse device paths or call local file delete from account deletion. A successful Cloud deletion cannot prove or alter local storage.
5. Remaining risk: previously issued signed R2 URLs are independent credentials until expiry (or separately authorised key rotation); existing deployed workers/services keep whatever code is currently running until a controlled rollout. A rollback to an older unsealed binary can reopen old routes; release controls must forbid that rollback without an explicit security review.

Plan v1 objects, Stripe subscription records, price mapping and webhook idempotency remain. This is a product admission decision, **not** an automated migration or cancellation.
