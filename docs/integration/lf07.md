# LF07: Secure local-first command protocol — integration contract

**Branch:** `feat/lf07-control` (based on `0c114859a4f2f13c264dcbd0cba2808d422a97da`)  
**Owner:** LF07 only. ADR-0462/0469 accepted designs remain independently unverified.  
**Implementation:** `selecta.lf_control` is a standalone service layer. **No production HTTP routes or playback/audio execution are installed by this PR.** Legacy routes remain unchanged.

## Why this is a separate protocol

The old `playback.session.submit_command` changes a cloud session immediately; it cannot prove that the physical speaker received or played a command. LF07 does **not** change that legacy behavior. New clients must select this protocol only after the engine capability handshake, with explicit migration gates. `created`, `authorised`, `queued` and `delivered` are *control-plane delivery observations*, not music playback. Only an engine-confirmed result may progress `accepted -> applied -> acknowledged`; actual audible output is represented by a separate `playback_observed` local event.

## Interface and payloads

`CommandEnvelope.parse(dict, now=server_clock)` validates **exactly** the v1 fields: `schema_version`, `operation_id`, `actor_id`, `actor_role`, `workspace_id`, nullable `zone_id`, `target_device_id`, `expected_generation`, nullable `expected_recipe_revision`, `policy_version`, `sequence`, `command`, `arguments`, `created_at`, `expires_at`, `idempotency_key`. IDs are opaque, bounded and never paths. Canonical JSON is HMAC-SHA256 signed with a per-device, per-rotation command key. The device verifies signature **and** independent `LocalScope` policy/generation/revision. Reject unsupported versions (no downgrade). Reject unknown fields, nested arbitrary arguments, shell/path/URL keys, unknown commands, NaN/duplicate JSON keys, oversized messages. No audio bytes, local paths, fingerprints or source-folder capabilities cross this boundary.

| Command class | Values | Maximum TTL | Reconnection |
|---|---|---:|---|
| Ephemeral | `play`, `pause`, `skip`, `seek` | 60 s | Never replay after expiry; accepted-but-unconfirmed is unknown, never speculative re-execution |
| Durable | `set_volume`, `set_schedule`, `set_policy`, `steer`, `reorder`, `approve_request` | 7 d | Only with checked generation, recipe revision and policy; older revisions conflict, not overwrite |

Strict v1 argument shapes: Play/Pause `{}`, Skip optional `song_index`, Seek required `offset_ms` and optional `song_index`, volume 0–100, schedule `{schedule_id, revision, enabled}`, policy `{revision, enabled}`, steer `{direction}`, reorder `{occurrence_ids}` and approve `{request_id}`. A new action requires a protocol/schema review; arbitrary file or process calls are prohibited.

`ActorScope` must be constructed by the existing authenticated cloud identity/role/zone service, not by copying actor fields from untrusted JSON. Cloud calls `authorise_actor`, and local independently calls `authorise_local` against its trusted locally cached scope/policy. Viewer cannot control anything; only owner/admin may change schedule or policy; staff cannot mutate mixes. A revoked device should not receive further commands; local cached-policy revocation takes effect when securely synchronized. **An offline stolen machine cannot be remotely switched off instantly.** Short credential lives, rotation, cloud-side revocation, and operator physical isolation are required.

## Pairing / credentials

`CredentialRegistry(path, master_key=...)` uses a **persistent secret-manager-provided** master key of at least 32 bytes and an independently configured SQLite database. The master key is **not** placed in the DB. `issue_pairing(actor, zones, now, ttl<=300)` produces a cryptographically random, one-time code scoped to the authorised actor's workspace/zones. `propose_pairing(code, device_id, challenge, now)` records a pending device identity without granting authority; a separately authenticated owner/admin calls `approve_pairing(actor, request_id, now, confirmed_challenge=...)` after verifying the locally displayed challenge and device; then `redeem(code, device_id, request_id, challenge, now)` atomically consumes the one-use code and returns a high-entropy device token and independent signed-command key. Only hashes of device tokens and pairing codes are stored. `authenticate` checks workspace and expiry with constant-time digest comparison. `rotate` invalidates the old token/signing generation; `revoke` disables future cloud authentication. The engine must store its token/key in OS-protected credential storage, never a repo config file.

**Deployment gate:** Pairing proposal and explicit authenticated owner approval are implemented, but the UI/route adapter must verify the locally displayed challenge and device details independently. A stolen code alone cannot redeem; a user who incorrectly approves a malicious proposal can still grant it access. Never approve automatically or without human device verification. Never expose that code in logs/telemetry. TLS validation, rate limits, human confirmation and abuse monitoring belong to the route adapter; neither an unauthenticated discovery API nor a public local file server is implemented here.

## Durable command / event stores

`ControlJournal(path, limit=4096)` is separate on cloud and local engines, using SQLite with atomic `BEGIN IMMEDIATE` checks. It stores command digests, idempotency keys, state history, high-water sequence fences, expiration, and bounded per-device queues. Outbox events are allowlisted `command_result`, `device_state`, `playback_observed`, `configuration_applied`, with only typed metadata. Sequence counters survive acknowledged-event compaction; replay and conflicting same-key operations fail closed. A bounded durable cloud-side receipt window checks both event IDs and canonical payload digests; old receipts outside the window fail with `event_replay_unverifiable` instead of being silently re-ACKed. The cloud inbox buffers out-of-order events, processes only contiguous sequences, and independently acknowledges each **after** its reducer handles the event. Gaps and reducer failure remain durable. Never discard unacknowledged events on storage pressure; return `outbox_full` for operator recovery.

`CloudCoordinator.queue(envelope, trusted_actor, now=...)` checks user scope **and active, non-revoked device registration**, then creates, authorises, and queues the signed envelope; no engine bearer token is needed by a human browser/controller. An optional `credential` parameter exists only for internal compatibility checks and must never be accepted from a cloud UI request. `delivered` is only transport receipt. `AgentControl.receive` verifies generation, signature, device scope, policy, speaker generation, locally cached authenticated actor roles and recipe revision before calling its injected `LocalExecutor`. On a failure after durable local acceptance, the command remains **unknown**; retries do not run Play/Skip twice. `AgentControl.report` creates a deduplicated, atomically sequenced outbox event that `CloudCoordinator.reconcile` checks under the current device credential before applying and acknowledging; duplicate/replayed event ACKs are reissued so lost receipts do not trap the local outbox. `OutboundAgentPump.once` automatically reports and flushes device events over the injected outbound transport. `HTTPSOutboundTransport(https_origin)` implements TLS-verifying outbound-only polling at `GET /api/local-first/v1/engine/next` and metadata-only event submission at `POST /api/local-first/v1/engine/events`. It sends bearer credentials only to the installed trusted HTTPS origin, refuses redirects, rejects cross-workspace commands and unrecognised ACKs. It does not install cloud server routes; the cloud integrator must explicitly mount those exact paths and authenticate engine credentials using `CredentialRegistry.authenticate`, calling `event_from_wire` to parse each event before reconciliation. Cloud refuses unconfirmed audio execution.

**Recovery:** Run `discard_stale(now, workspace, device, minimum_policy=...)` on reconnection and after policy changes; stale and expired pending commands go terminal. Restore of a cloud database from backup must require device credential rotation/rehandshake and monotonic sequence/epoch reconciliation before enabling remote actions. A restored old counter or an offline original speaker is **not** evidence of safe takeover.

## Exact integration hooks (other agents own them)

1. **Cloud route owner / final integrator:** mount the exact versioned `GET /api/local-first/v1/engine/next` (outbound-engine long/short-poll) and `POST /api/local-first/v1/engine/events` (response `{"schema_version":1,"acknowledged_event_ids":[...]}`) adapters backed by `CloudCoordinator`. Authenticate every call with the engine bearer credential, verify workspace/device headers against the authenticated registration, parse signed command/event wire formats with `SignedCommand.from_wire`/`event_from_wire`, and never return media or local file paths. Queue commands under a separately authenticated human `ActorScope` using `cloud.queue(envelope, scope, now=...)` **without ever receiving the engine bearer credential from a browser**. Instantiate `CredentialRegistry` with secret-manager `master_key` plus a persistent SQLite store (or replace with a production SQL adapter). Provide JWT-authenticated routes for pairing offer/approval/redeem/revoke/rotate, command queue and outbound engine channel, incorporating tenant membership and fresh zone policy. Enforce TLS, Origin/CSRF/Host/DNS-rebinding checks on any loopback administrative endpoint, and use outbound engine auth rather than CORS as security. Do **not** register these routes from LF07.
2. **Agent 01 (`src/selecta/local_engine/**`):** at bootstrap, load OS-protected credential and persistent journal. Supply `LocalScope` from local policy/generation state, including trusted `authorised_actors` mapping. An untrusted signed envelope may not supply its own role authority. Use `HTTPSOutboundTransport` (or implement `OutboundTransport.connect`, `send_events`, `receive_command`, `close` over an authenticated **outbound** TLS connection) with bounded message framing, retry/backoff and heartbeat. Mount no public media endpoints. Wire `OutboundAgentPump(agent, transport, now=...)`, and do not treat cloud leases as output truth.
3. **Agent 08 (`src/selecta/playback/**` except commands):** supply the `LocalExecutor(CommandEnvelope) -> ExecutionOutcome` port. Perform actual generation/recipe checks within the same device-ownership transaction, preflight physical output and local recording, and return `output_confirmed=True` only after real execution (pause/stop release or audible output). Preserve old speaker on failed takeover. For fencing and cross-device simultaneous transfers, Agent 08's authoritative generation must be the `LocalScope.generation`. Local `playback_observed` events can update UI; never infer them from `queued`.
4. **UI agents 10/12/13:** show queued/delivered as pending, acceptance as pending until observed confirmation, and failures with truthful codes. Controller-only devices cannot import local source paths through command arguments. Legacy clients remain on legacy API until capability negotiation and E2E verification.
5. **Database migration owner Agent 04:** LF07 owns *no* repository Alembic revision. The two self-contained SQLite stores are integration-stage persistence; a deployment can migrate their schemas into shared Postgres under the sole migration owner's contract. Do not edit global API registration or migrations here.

## Focused validation and unresolved gates

Run `PYTHONPATH=src pytest -q tests/test_lf07_*.py` (26 passing in the isolated Agent 07 overlay; full repository CI not yet verified). Focused tests cover code expiry/one-use copying, owner-approved challenge enrollment, rotation, revocation/cross-workspace denial, invalid paths/URLs/shell, schema downgrade, HMAC forgery, local actor-role/policy/zone/generation/revision fences, duplicate and out-of-order commands, idempotency, delayed acknowledgments, a simulated outbound channel under lost ACKs, disconnected outbox/inbox replay, compaction, storage pressure, unknown output, stale offline buttons and multiple controllers. Live TLS, authentication route adapters, 10k-engine load, 30-day soak, backup/restore drills, owner-confirmed pairing UI, local physical output and operational revocation audits remain **integration/release gates**, not claimed verified by this PR. Independent review needed before retiring existing cloud controls.
