# LF17 — hosted-audio migration and account archive

**Branch:** `feat/lf17-migration` (based on ADR PR #64, `0c114859a4f2f13c264dcbd0cba2808d422a97da`).  
**Scope:** read-only inventory, verified-reference planning, operator-approved adapter, metadata-only personal archive, historical retrieval policy and integrity audits. **No production migration has run.**

## Contracts and data locality

The existing R2 paths are `originals: w/{workspace}/a/{asset}`, `derived: w/{workspace}/{kind}/{hash}/attempts/{attempt}/{name}`, `exports: w/{workspace}/x/{id}.flac`, and `staging: s/{upload_id}/object`. LF17 reads the existing `assets`, `upload_sessions`, `artifacts`, `revision_artifacts`, `subscriptions`, `entitlement_snapshots` and deletion-ledger tables via a workspace-scoped RLS transaction. Live R2 originals/derived/exports are listed only below that workspace's prefix; staging is **HEAD-only** for that workspace's active upload sessions (never enumerate a global staging bucket). Passed backup manifests are reviewed separately. It is impossible to certify backup deletion from a live R2 listing alone.

`collect_inventory(engine, workspace_id, objects=client, backups=operator_backup_manifests)` returns an immutable-shaped JSON snapshot with assets, upload state, protected virtual revision artifacts, links, subscribed plan/version, tombstones, object observations, missing objects, orphan objects, and integrity warnings. With `objects=None`, the report is incomplete for retirement by design. Listing failures and scan limits raise `IncompleteInventory` and block go/no-go; they do not misclassify missing evidence as absence.

`audit_references(snapshot, known_foreign_asset_ids=...)` detects dangling legacy IDs, foreign asset references from a separately authorised privileged audit, damaged revision parentage, unprotected history and inconsistent tenant ownership. `dry_run_report(snapshot)` summarises customer data without touching it. `deletion_readiness(snapshot, gates=...)` **always** emits `destruction_authorized: false`. It blocks for incomplete inventory, missing backups, active historical assets, unfinished uploads, missing or conflicting references, unreconciled backup manifests or any unconfirmed gate. The required gates are migration completion, local-engine parity, customer retrieval completion, legal approval, delivered notices, expired retention, backup reconciliation, replayed deletion ledger, tested disaster restore, closed legacy upload admission, old-client upload denial and absence of legal holds.

## Agent 04 recipe schema boundary

Existing Cloud mix revisions are protected virtual `artifacts(kind="mix_revision")` with immutable content-addressed `mix_contract` documents in `provenance.settings.contract`. **Agent 04 alone owns database migrations and the final canonical physical recipe schema.** This work never rewrites, replaces, deletes, or rehashes those historical contracts. There is intentionally no new Alembic migration.

`plan_backfill(workspace_id, legacy_revisions, verified_bindings)` validates the existing `mix_contract` version and revision hash and outputs the explicit intermediate `selecta.lf17.recipe-sidecar/1` projection. It supplies a stable occurrence ID per position, including repeated songs; `legacy_asset_id`, original revision and parent are unchanged. A canonical track ID can appear **only** when a `VerifiedLocalBinding` carries an exact same-tenant canonical ID, device ID, recording revision and local verification proof. A missing or candidate match remains `resolution="unresolved"`, `canonical_track_id=null`. Verification on one device is **not** a claim that other devices are ready; raw hashes, local paths and raw fingerprints are not published.

`LocalPlanJournal(path).prepare(plan)` validates the plan SHA-256 and atomically fsyncs a LOCAL progress record. Repeating a prepare or checkpoint is idempotent. Crash before replace keeps the old journal; replay resumes after read. `restore_legacy_revisions(plan)` reconstructs every old contract without fetching or fabricating media.

**Integration wiring to be done after Agent 04 publishes its canonical schema:** implement the `RecipeProjectionWriter` protocol in Agent 04's owned code: `recipe_schema`, `upsert_sidecar(workspace_id, legacy_revision_id, sidecar, idempotency_key)` and `rollback_sidecar(...)`. Its writer must authorize the tenant, version-check inputs, protect the immutable revision DAG, and perform a transactional idempotent upsert keyed on the supplied `plan_id:revision_id`. An operational runner must explicitly supply `approved=True` and its expected actual `recipe_schema` to `apply_prepared_plan`; the default is refusal. If the response is lost after a successful upsert, re-running the same idempotency key is safe. `rollback_prepared_plan` compensates only added migration projections in reverse order; legacy history and user-owned files are not deleted. The driver never writes to a production database on its own. Until that adapter and its tests exist, **this is staged planning, not a completed live canonical database backfill**.

## Personal account archive / legacy retrieval

`GET /api/account/export?mode=metadata` returns a ZIP containing:

- `manifest.json` version 2: explicit metadata-only scope and no local recordings.
- `settings.json`: authenticated account, personal workspace, plan, preferences, Lucy choices and registered devices.
- `assets.json`: historical Cloud asset IDs, size/format/time, no original audio bytes.
- `mixes.json`: all historical protected and unprotected virtual revisions recorded verbatim (with damage flags), immutable lineage and last playback session.
- `billing.json`: subscription status/price references and historical plan entitlement versions, excluding payment details.

The endpoint never asks the local engine to send music. It does not open, scan, erase or claim to back up user-owned local files, stems, selected exports or private bindings. Account erasure is implemented elsewhere; the LF17 audit explicitly calls out that no account deletion may unlink unrelated local originals. The archive uses `Cache-Control: no-store` and an authenticated personal-workspace ownership check.

For existing clients, `GET /api/account/export` and explicit `?mode=legacy` preserve the pre-existing full ZIP with original R2 bytes and SHA-256 verification. This compatibility mode is a **transitional legacy endpoint**, not the future local-first default. New deployments should inject `legacy_retrieval_grant_factory` into `cloud_export.install_routes` and only grant reviewed, workspace-specific, revocable, notice-versioned and ≤90-day `RetrievalGrant` records. That injected policy fails closed when a grant is missing/expired; the factory is optional only to preserve unmodified old-client deployments during transition. To remove default legacy access at cutover, deploy the gating policy and deny all grants once the contractual window ends; simply hiding the UI is insufficient. The standalone `retrieve_original` helper additionally checks asset ownership, canonical R2 key, HEAD size/SHA and the full downloaded hash, and removes partial output on failure. It provides no upload or delete capability.

## Safety and disaster-restore checks

The tests under `tests/test_lf17_migration.py` cover deterministic repeated migration, verified versus missing and cross-tenant matching, unchanged old contracts, repeated occurrences, protected virtual revision metadata export, interruption before journal swap, a network failure after an otherwise successful projection upsert, schema-version rejection, compensating rollback, interrupted R2 scan, missing R2 objects, cross-tenant references, expired/revoked grants, old-client export behaviour and synthetic disaster restoration.

Before pilot/customer execution: (1) implement and test Agent 04's writer; (2) review customers' audio rights/retention/legal holds/notices and legacy retrieval policy; (3) inventory complete production and offsite backup manifests read-only; (4) exercise simulated bad restore with old client and closed upload routes; (5) reconcile all unresolved and cross-tenant IDs with customer repair paths; (6) obtain independent sign-offs from the release-gates ADR. Keep all audit reports outside audio storage and protect personal metadata. **This branch contains no R2 purge and no infrastructure teardown.**
