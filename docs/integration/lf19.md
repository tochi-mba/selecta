## What is available now

- `tests/lf_harness/fixtures.py`: five independent device identities, directories, source mounts, catalogue files and output directories. Engines A/B share workspace A but have **5/8 and 8/8** canonical recordings respectively; separate controller phone/browser own zero media or outputs; foreign engine belongs to workspace B. Stable occurrence IDs intentionally differ from local media file IDs. All input media are generated locally; no customer audio or third-party samples.
- `audio.py`: deterministic real PCM/WAV files, per-recording fingerprints retained **only inside the local fixture**, independent content validation and byte-level corrupt/restore helpers.
- `network.py`: virtual millisecond clock, deterministic delay, directional/bidirectional partition, disconnect/reconnect, targeted packet drop (including missing ACK), deterministic reordering and packet delivery history. No real sockets or wall-clock sleeps.
- `faults.py`: crashed engine, physically detached/restored source directory, missing output, truncated media, stale heartbeats, deterministic ENOSPC, CPU/RAM/GPU/thermal pressure and engine power-cycle generation changes.
- `playback.py`: independently testable overlap oracle for physical-output collisions and conflicting same-zone devices; distinct output/zone intervals are allowed. Simulation of preflight, concurrent takeover, idempotent retry, generation fencing, missing media and old-speaker partition refusal. **Simulation is not production evidence.**
- `venues.py`: IANA timezone and UTC-stepped wall-clock simulations, overnight schedules and weekday ownership, spring/fall DST folds, 24-hour openings, multiple independent zones, output collision refusal, prolonged offline operation, deduplicated local event journal and power-restoration gate (hours, local checkpoint, policy, rights, output readiness).
- `security.py`: nested JSON/base64 WAV probes, mislabeled MIME, sample arrays, log attachments, path leakage and cross-tenant commands; capture oracle checks recognizable synthetic media and local paths. **These signatures do not constitute a complete cloud egress proof**; Agent 02 must supply route-level policy enforcement plus byte-level capture in staging.
- `contracts.py`: versioned recipe shapes, bounded availability contract assertion for target device/revision and states, command scope/TTL/generation checks, cloud ACK truth and importable production adapter protocol.
- `acceptance.py`: strictly opt-in production adapter seam requiring real engine provisioning and instrumented control-plane assertions. Invalid readiness, unsafe takeover, cross-tenant access, forbidden media ingress and leaked egress produce FAIL, never silent skip. Physical-output acceptance is deliberately BLOCKED pending independent hardware measurement.
- `evidence.py`: atomic JSON report with test case, task/ADR, source SHA, real outcome, expected/actual, execution environment, UTC date, reviewer, evidence link, residual risks, migration stage and next decision. Go/no-go calculation counts only independently evidenced integrated/physical PASS; simulated or harness self-test outcomes cannot close a release gate.
- `web/e2e-lf/`: optional browser probes for device-specific 5/8 readiness, controller-only state, partition refusal, stale media, truthful venue output and 400% zoom; these require actual integrated fixture URLs and test IDs, not fabricated DOM or skipped assertions.

## Harness self-test and evidence generation

From the root of the integrated repository, using Python 3.12+; no application deps required:

```sh
python -m unittest discover -s tests -p 'test_*.py'
python tools/lf_harness/run.py self-test --out /tmp/selecta-lf19-harness.json
python tools/lf_harness/run.py acceptance --out /tmp/selecta-lf19-acceptance.json
# Last command MUST exit 2 and report all required cases BLOCKED if no adapter is installed.
```

Running the first command on the *entire* production `tests/` directory will discover other application tests, which may require repository dependencies; to target LF19 alone use:

```sh
python -m unittest discover -s tests/lf_harness -t tests -p 'test_*.py'
# Or run `python -m unittest discover -s tests/lf_harness -t tests -p test_*.py`.
```

The self-test runner enumerates every discovered test result before executing (unittest mutates suites) and writes real per-case results. JSON results belong in a CI artifact location or `/tmp`, not checked into the repository or treated as deployment sign-off.

## Required integration contract

The ADR's [API contracts](../adr/selecta-local-first-api-contracts.md) are **schematic only**. Do not invent a deployed endpoint. Agents 02, 03, 04, 07, 08 and 09 should provide a separate (non-LF19-owned) `module:adapter` with `AcceptanceAdapter` methods in `tests/lf_harness/acceptance.py`. Adapter must:

1. Provision real isolated local engines from trusted fixture directories **locally**, with separate scoped identity and output, and two real controller contexts; do not send audio/fingerprints/filesystem paths to the cloud. Fixture files remain in temporary folders, destroyed on cleanup.
2. Register actual capabilities and authenticate workspaces; query real local catalogue verification for 5/8 and 8/8 recipe revision, preserving candidate/mismatch/missing states instead of treating title-only similarity as ready.
3. Exercise two simultaneous takeover attempts with the same expected generation, lost ACK/replay, and old-speaker partition; return authoritative command states and instrumented actual output intervals. A cloud lease or heartbeat is **not** an output measurement. Do not infer gapless transfer.
4. Reject cross-workspace device actions and revoked credentials in the actual control plane.
5. Run negative media payload checks in a **local or isolated staging ingress interceptor** before any cloud call. Capture actual egress; never upload forbidden synthetic audio to production while testing the deny rule.
6. Return deterministic, sanitized results and destroy all allocated credentials/devices/processes in `close()`. Inject disk, drive, CPU/GPU, clock, and crash faults through the corresponding real implementation seams (the LF19 helpers can supply deterministic scenarios).

After integration, and only with an independent reviewer and durable run evidence:

```sh
python tools/lf_harness/run.py acceptance \
  --adapter selected_integration.adapter:instance \
  --reviewer independent-reviewer-id \
  --evidence-link https://example.invalid/real-evidence-to-be-supplied \
  --out /tmp/selecta-lf19-acceptance.json
```

The example URL is a placeholder, **not** acceptable proof; supply an actual archival run link. The runner always reports NO-GO while `physical_output_measurement` is BLOCKED. Hardware acceptance requires independent measurement (acoustic loopback or instrumented DAC capture with known calibration), two physical speakers, positive playback and enforced silence traces, valid original/master identification, output routing, six-hour offline soak, power-cycle recovery and reviewer sign-off. Never rename a simulation or process heartbeat as measured output.

## Gate matrix (current truth)

| Scenario | Harness verification | Integrated Selecta verification | Independent physical verification |
|---|---|---|---|
| Two engines and 5/8 recording availability | Self-test PASS | BLOCKED until catalogue/recipe adapter | User relink drill required |

## Final LF integration and release conditions

- Do not modify other agents' production files or tests to satisfy the harness. Resolve schema/selector mismatches through an explicit adapter or integration-owner change.
- Map old hosted upload/proxy/render tests to new routes and parity before retiring existing tests; do not silence global CI. Retained standalone features still require end-to-end tests and music quality reviews.
- Release decision follows `selecta-local-first-release-gates.md` LF-G01..G13 and verification LF-V01..V17. A PASS from the standalone harness is **never** LF-G04/LF-G05 approval.
- Evidence records must include source SHA, named reviewer **different from implementer**, environment details, expected and actual results, immutable link to traces/logs, risks and next decision. Record missing implementation as BLOCKED, failing behavior as FAIL, non-independent pass as unverified.
- Known limitations: fault/network/resource models are deterministic simulations, not kernel-level network shaping, actual drive removal, hardware DAC contention or acoustic measurements; synthetic-audio signatures alone cannot prove absence of all reconstructible derived audio or covert transfers. Real acceptance requires independent capture and qualified review.
