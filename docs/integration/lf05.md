# LF05 — Device-local DSP job execution and resource safety

## Current DSP parity

The existing durable JobStore and work.sqlite remain the authorities for job identity, operation idempotency, dependency DAGs, persisted progress, cancellation, retry/backoff, restart recovery, immutable receipts and fenced result publication. LF05 deliberately retains the **actual** DSP algorithms:

| Job | Preserved algorithm | Device executor |
| --- | --- | --- |
| analyse.song | analysis.pipeline.analyse_song | workers/local_analysis.py |
| seam.render and stem splitting | SeamStore.render_now, existing stem separation | workers/local_seams.py |
| export.render | mix.export_snapshot and verify_export | workers/local_exports.py |
| lyrics.fetch | existing lyrics lookup | Local lightweight thread |

The new LocalResourceGovernor acts at dispatch and existing cooperative check-ins. It does not copy, reimplement or approximate any audio algorithm. Existing WorkerRunner users without an optional governor behave as before, including hosted workers and migration paths.

## Resource ownership and safety

All local worker processes open an additional device-private SQLite database at engine-home/lf-resources.sqlite. This contains only **attempt reservations** and physical audio-zone deadlines, never music. A BEGIN IMMEDIATE transaction atomically limits concurrent heavy jobs across separate analysis, seam and in-process export workers. Each capacity permit uses a unique attempt token and an expiring, renewed lease; stale ownership cannot overwrite a new attempt. Crashes leave only expiring permits.

The governor measures CPU utilisation, logical CPU count, available RAM, free disk, optional local NVML GPU free memory, thermal warning and low battery. It refuses GPU-heavy jobs if GPU capacity is unknown. It reserves CPU headroom for the operating system and each active audio zone. Near-deadline, high-CPU, hot, low-disk or low-memory conditions prevent or cooperatively interrupt background DSP. The pre-existing JobStore continues to enforce priorities within a pool, cancellation, dependency promotion and fenced publishing.

Priority order is ACTIVE_PLAYBACK, IMMINENT_TRANSITION, NEAR_TERM_HORIZON, URGENT_REQUEST, USER_EDITING, ANALYSIS, SPECULATIVE. Existing analysis/seam/export rank mappings are in lf_jobs.contract.priority_for_legacy. A physical zone with unknown deadline is treated as imminent, not assumed idle. An otherwise idle single-core device may work; a single core with active playback cannot run heavy background work. A denied capacity permit releases rather than fails the durable claim, preventing false success or a consumed retry.

Device-local policy no longer differentiates paid plans by CPU weights, worker slots or daily speculative compute allowance. Physical resource bounds still apply. No music is sent to hosted workers by these changes.

## Typed integration — Agent 06

Import ExecutionRequest, ExecutionReceipt, JobKind, JobPriority, SourceResolver and validate_sources from selecta.lf_jobs. ExecutionRequest includes operation ID, workspace, job kind, exact source revisions, recipe/algorithm revisions, idempotency key, priority, optional dependencies, zone ID, deadline, scratch, memory and GPU requirements. Each idempotency key should include every algorithm, recipe and source revision that changes its output.

ExecutionReceipt contains only operation/attempt IDs, fenced generation, state and version references, with an optional error code. It contains no paths or user media.

Resolve canonical recording/version pairs through a **private device-side** SourceResolver immediately before DSP. validate_sources refuses absent or unauthorised paths, altered revisions, unverified equivalents and disconnected drives; it never guesses replacement media. LocalSource itself is not cloud-serializable. Agent 06 owns artifact provenance, final cache/export identities, eviction and persistent export validation. Its writers should use JobStore's existing fenced completion and provide realistic scratch budgets.

## Typed integration — Agent 09

Create one LocalResourceGovernor with the shared engine home. When the **physical output owner** starts or updates a zone, call:

    governor.observe_zone(ZoneDemand("zone-a", True, deadline_at=next_deadline_epoch))

When that speaker has actually stopped:

    governor.observe_zone(ZoneDemand("zone-a", False))

Agent 09 owns the real zone policy, active-output truth, hardware state and transitions. Never clear physical ownership merely because a remote controller or cloud connection is offline. Five active zones consume five reservations and share remaining CPU capacity across all DSP worker processes. The protocol uses epoch seconds for deadlines to work across processes.

**Integration gap:** this PR provides the working governor and worker hooks. Agent 09 still needs to wire the real output lifecycle to observe_zone. Agent 03 needs to supply its canonical local source bindings; Agent 06 needs to connect its new artifact requirements. Those directories are deliberately untouched.

## Failure coverage and remaining gates

The focused test suite tests CPU exhaustion, RAM pressure, disk full, unknown GPU capacity, heat and low battery, imminent physical deadlines, multiple zones, cross-process capacity, duplicate attempts, crash/lease expiry, stale close, cancellation, crashed decoder, immutable source revision checks, dependency blocking and tier-neutral local policy.

Run:

    pytest -q tests/test_lf05_jobs.py tests/test_local_work_host.py tests/test_local_durable_jobs.py tests/test_local_durable_seams.py

There must also be independent physical-device rehearsal for five concurrent zones, underrun deadlines, low-battery/thermal operation, forced decoder termination and interrupted large exports. The draft PR is **not** independent release verification.

## Migration and rollback

The existing core.durable_local_jobs feature flag still controls the original durable job host, and legacy non-durable paths remain. Hosted paths and billing history are not removed. work.sqlite keeps its normal, existing restart/lease recovery semantics. Rolling back LF05 leaves that file unchanged; the LF-specific resource sidecar can remain or be removed after stopping all new local workers because it holds no music, recipes or immutable results. Agents should not treat a locally accepted DSP job as proof that a remote speaker actually played music.
