## What changed

The existing business routes and navigation stay intact. HQ gets a fleet readiness summary (including 20+ venue grids), venue managers see per-zone local inventory, output, horizon and actionable recovery, staff get a single plain-language speaker line, and device-first onboarding replaces cloud-upload language when the new flag is enabled. Final onboarding activation is blocked in the UI until every zone supplies current affirmative local evidence.

The existing business interface remains untouched when \`org.features['business.local_first'] !== true\`. This intentional opt-in prevents older servers and workspaces from implying local audio is available.

The kiosk's autoplay probe unlocks a silent AudioContext but now always reports \`playing() === false\`: only a genuine local playback implementation may assert playback. The kiosk state machine requires \`playingConfirmed === true\` before showing either Playing or Playing from saved music. Unsupported audio runtime implementations safely show a short problem code instead of fictional playback. The guest allowlist additionally discards obvious filesystem paths and stack traces.

## Agent 09 / controller integration contract

The UI uses the existing \`businessClient(...).overview(org)\` payload, never new unverified endpoints and never backend policy logic. Agent 09 (or the integrated controller projection) should supply an optional \`local_first\` field **on each zone**. The complete TypeScript contract is \`LocalZoneReport\` in \`web/src/business/localFirst/readiness.ts\`:

| Field | Evidence required |
| --- | --- |
| \`verified_at\` | Authoritative engine verification time in UTC epoch **seconds**; not browser fetch time |
| \`engine.state\` | ready / starting / stopped / crashed / offline_playing / unknown |
| \`engine.update_required\` | True if the installed agent cannot safely continue without update |
| \`source.state\` | connected / disconnected / permission_required / missing / unknown |
| \`inventory.verified\`, \`inventory.required\` | Exactly verified local recordings over all required local recipe occurrences, **N/M** |
| \`horizon\` | Committed, prepared, planned and eligible offline fallback in **minutes** |
| \`output.state\` | playing / idle / failed / silent / untested / unknown |
| \`output.physical_verified\` | Server-verified real speaker output, not AudioContext unlocked or command accepted |
| \`output.device_name\`, \`output.generation\` | Safe display label and ownership fencing generation, not a file/system path |
| \`policy_approved\` | Authoritative eligibility decision (rights owned by Agent 09) |
| \`offline_rehearsed\` | Verified on-site network-disconnect rehearsal with continuing local playback |

All fields are bounded metadata. **Do not include file paths, content fingerprints, PCM, stems, audio bytes, signing material, full licences or privileged errors.** A zone can only be Healthy with a fresh report, ready engine, connected authorised source, exact N/M, prepared >= 15 min, fallback >= 30 min, verified physical output, policy approval and completed offline rehearsal. A zone with missing reports or stale (> 120 s) verification is Unknown; an explicit \`offline_playing\` report can be shown as **Offline (last known)**, never as proof of current music. The browser-offline condition likewise never turns into Healthy.

These thresholds are conservative **UI indicators only**. Agent 09 is the authority for legal/rights, schedule activation, job preparation, offline engine status, and speaker transfer. The server must independently enforce all activation and takeover gates; disabling a web button is not security. Agent 07 provides command semantics; Agent 14 owns Rooms and requests; Agent 13 sends neither audio nor playback-ownership commands.

## Operational journeys

1. **Venue setup:** create venue/zones; connect a permitted local source on the venue computer; pair a local engine using the existing pairing form; verify a physical speaker output; confirm music policy; prepare transitions and fallback; rehearse offline playback; refresh authoritative reports. The local feature flag changes the Music, Pair and Service steps without changing the persisted setup step identifiers.
2. **HQ:** view Healthy, Degraded, Silent, Offline and Unknown counts, then open a specific venue. First 20 venues render with a Show all control for larger fleets; the original sortable/keyboard-accessible HQ grid remains.
3. **Venue manager:** inspect every zone's exact N/M, prepared/committed/planned/fallback horizon, speaker, physical output, generation and verification timestamp; select recovery directions for drive disconnect, permissions, missing recordings, speaker failure, outdated agent, insufficient fallback, missing rehearsal or policy. Refresh only rereads reports. It **does not test speakers, restart engines or claim success**.
4. **Staff:** retain Now Playing, Skip, Bigger/Calmer, Requests and bounded Volume. Show only a small speaker-status sentence. Existing offline command semantics and PIN protections are unchanged; managers hold diagnostic context.
5. **Kiosk:** an unlocked silent context is not an actual speaker. \`playingConfirmed\` comes solely from a real local playback implementation. Public screens continue using the allowlisted kiosk view; hidden staff panel remains PIN-protected when required and must not receive business billing/management fields.
