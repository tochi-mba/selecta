# LF18 — Hosted audio sunset and privacy-safe local-engine fleet

**Branch:** feat/lf18-infra, based on ADR head 0c114859a4f2f13c264dcbd0cba2808d422a97da.
**Ownership:** infra/, services/worker/, optional workflow changes, new lf_fleet package
and LF18 tests only. **Status:** integration candidate; no service has been retired.

## Scope and current deployment findings

The repository still describes Modal EU CPU light/heavy, T4 stems + CPU fallback and
export workers; pool capacity and cost ceilings in infra/workers/pools.json; a hosted
worker container with a locked beat_this.small0 model; Render worker gateway; Modal
autoscaler in the maintenance leader; signed R2 URLs; four audio buckets (originals,
derived, exports, staging), deletion ledger and offsite originals backup; and staging
and production original-copy cron schedules. The release shell still deploys Modal,
Render and Cloudflare automatically on main.

Specific mixed/protected dependencies: Render API and maintenance, Cloudflare Terraform
containing both audio and Pages/DNS/WAF, Render secret groups containing audio and
WorkOS/Stripe/AI keys, backup scheduler with DB dumps beside originals, and legacy
alerts/SLOs. These must be split in a later, independently reviewed cutover, never
deleted by a blanket Terraform destroy or a global service disable.

The manifest infra/retirement/inventory.json inventories 31 source-defined assets
with classification audio (future removal candidate), mixed (manual split only), or
retain (must survive). Source inventory **does not prove live assets exist or are empty**.
Before retirement, operators must inspect cloud accounts, actual object versions,
backup inventories, historical URLs, DNS, retained credentials and spending.

## Read-only commands

From the repository root with Selecta installed:

    python -m selecta.lf_fleet audit --root .
    python -m selecta.lf_fleet plan --root . --environment staging
    python -m selecta.lf_fleet plan --root . --environment production

An optional --evidence file supplies JSON containing schema_version=1, environment,
and gates keyed by gate identifier. Each attestation contains passed=true,
independent=true, evidence_id, reviewer_id and confirmed_at (timezone-aware ISO 8601,
no more than 90 days old). The planner reports missing gates and dependency blockers;
it prints neither reviewer details nor evidence payloads. An audit reports only
catalogued source paths and finding codes, never file contents or secret values.

There is intentionally NO apply, delete, terraform, modal, rotation or network
functionality in this implementation. Even a fully reviewable plan is not approval
to execute. Keep legacy retrieval and the current deployments in place.

## Ordered cutover gates

| Stage | Verification and boundary |
|---|---|
| inventory | No missing references, unclassified infra or unknown live assets; reconcile actual live cloud inventory outside this source audit |
| admission | Agent 02 enforces new-audio ingress denial; customer-approved historical retrieval remains accessible; notices signed |
| workers | Agent 05 DSP parity verified on real hardware; Agent 07 control channel operational; all hosted jobs drained and access preserved |
| gateway | Old worker transport can stop only after control API/agent commands work and any surviving retrieval is isolated; old clients fail closed |
| storage | Agent 17 migration signed; recipe resolution, customer retrieval window, legal holds, deleted-object ledger, backups and restore drill verified; signed data-owner and independent approvals |
| secrets | Zero original/derived/export/staging objects and backup remnants verified post-purge; zombie gateway and old URLs denied; storage/media-signing keys revoked in a separate approved operation |

The exact gate IDs are in REQUIRED_GATES in retirement.py. Stage reviewability
depends on both its own signed gates and all preceding stages. A false-positive
self-attestation does not override separate change review, approvals or production
validation. Preserve evidence of actual object counts, restore IDs, independent
reviews and authorised retention dates outside this repository.

## Rollback boundary

validate_rollback_scopes only permits cloud_control, metadata, database, and an
explicitly authorised approved_legacy_retrieval before purge. It always rejects
audio_uploads, audio_streaming, cloud DSP, cloud stems, worker gateway or a wildcard.
After purge there is no audio restore promise. Restore procedures must omit legacy
ingress/proxy deployment and old signing credentials. A code rollback does not
reverse the media deletion ledger or authorise rebuilding an audio locker.

## Privacy-safe fleet contract (integration with Agents 01, 07, 08, 09)

The authenticated and workspace-scoped outbound device transport (owned by Agent 07)
must assign received_at on the **server** before calling EngineReport.from_payload.
The strict allowlist permits opaque workspace/device/venue IDs; engine semver and
protocol; bounded source, output and playback states; prepared horizon, fallback
runway and offline journal delay in seconds; pending update, opening failure and
credential expiry. It rejects all extra keys including paths, audio, lyrics,
fingerprints, media hashes, debug traces and raw diagnostic attachments. Never log
the raw payload, add it to Sentry, or serialize this dataclass wholesale for metrics.

Health semantics:
- Healthy: fresh authenticated report, verified output, ready source and adequate
  horizon/fallback. Health is not a continuous microphone/audibility assertion.
- Degraded: disconnected/blocked source, output fault, shortage, pending update,
  delayed journal, opening failure or expiring/expired credential.
- Silent: device reports silent output while playing or scheduled.
- Offline: server has not received a heartbeat within 240 seconds.
- Unknown: missing report, stale over 60 seconds, bad server clock, or unverifiable
  output, source, horizon, fallback or journal. Never infer audibility from heartbeat.

Fleet summary and fleet_alerts return **counts** only. No workspace, venue, device,
track or user IDs in metric labels or logs. Alerts include stale agents, silent
outputs, failing venues, expired/expiring credentials and incompatible major/protocol
versions. Reconnect storms are deduplicated by workspace and device; verify a
1,500-zone burst, failover and clock skew in Agent 19's harness. Operators should
wire counts into authenticated support dashboards and add rate limiting/tenant
authorisation at transport ingress, not in this read-only analysis package.

## Ownership and staged dependencies

- Agent 02 implements the server-side audio egress prohibition and endpoint denial,
  **not** this agent. Do not bypass their API admission work.
- Agent 17 inventories user assets, migration/backfill, retrieval and legal holds.
  This manifest is infrastructure only, not a substitute for their data inventory.
- Agent 01 defines engine lifecycle/version, Agents 05/06 verify real DSP, Agents
  07/08 handle command/release safety and Agent 09 supplies output and venue state.
- Agent 19 supplies independent multi-device/partition/hardware test harness.
- Final integration must wire telemetry into the authenticated command channel,
  provide real venue on-call runbooks, remove old SLOs only after replacements
  exist, and verify hardware audio output. This branch intentionally changes no
  live deployment manifests, schedules, secrets or legacy customer retrieval paths.
