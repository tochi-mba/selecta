## Staged upload policy

SELECTA_LF_AUDIO_ROLLOUT_PHASE is **server-side only**, values:
- legacy: existing behaviour, intended for standalone/local compatibility or a strictly
  time-limited approved cloud migration exception.
- drain: refuse planning and starting new multipart sessions; permit only existing-session
  part signing, completion and promotion from staging to originals. No new derived media.
- sealed: refuse planning, signing, completion, promotion, R2 PUT/copy, hosted DSP
  preparation, derived-media artifact publishing and presigned write URLs. Deletions and
  recovery reads remain functional.

A deployed stage is any SELECTA_ENV except explicit local/test/development names (no
environment also retains the pre-existing local test/standalone default). Production and
staging default to sealed. A deployed non-sealed exception additionally requires both
SELECTA_LF_AUDIO_EXCEPTION_APPROVED=yes and SELECTA_LF_AUDIO_EXCEPTION_UNTIL as a
timezone-aware UTC timestamp in the future but within 30 days. Missing, malformed,
expired or unknown configuration fails sealed. Never accept a client-controlled mode
flag, a request header, an old app version, a tenant plan or an upload response as
an override. Rolling back to a legacy deployment requires explicit, audited operator
approval and a new bounded exception; no client can silently reverse cutover.

The independent SELECTA_LF_LEGACY_RETRIEVAL defaults to enabled, allowing
previously uploaded customers to fetch their authenticated historical originals and
derived media during Agent 17 migration. Set to disabled only after retrieval/legal
approval and migration/export parity, not merely after blocking uploads. Signed GET
URLs must remain short-lived and tenant-scoped. No existing object is deleted by LF-02.
The account ZIP flow is owned by Agent 17 and remains a historical export exception.

## Typed metadata-only boundary

Reusable API: selecta.lf_egress.validate_envelope(value, workspace_id=authenticated_workspace,
kind=PayloadKind.CONTROL). Accepts bytes, JSON text, or mapping with exactly four root fields:

- schema_version: literal integer 1
- kind: an explicit PayloadKind (recipe, control, catalogue, availability, schedule,
  play_log, ai_plan, diagnostic)
- workspace_id: must match the *authenticated* workspace, not the posted workspace
- data: a strictly allowlisted per-kind object, including recursively nested objects

Rejected: arbitrary or unknown keys, raw or binary body values, duplicate JSON keys,
unbounded lists, excessive depth, non-finite numbers, >64 KiB payloads, long free text,
local filesystem/UNC/file URIs, media/signing hashes, fingerprints, raw feature arrays,
stems/PCM/waveforms, lyrics, exports, attachments, credential-bearing diagnostics,
data URLs and base64/hex-encoded sound (including nested strings). Content sniffing
adds a secondary defence but does not infer permission from MIME types.

Errors use stable reason codes and never reflect untrusted payloads or filesystem paths.
safe_audit_fields(code, kind) returns only fixed, scrubbed values; do not log request
bodies, presigned URLs, payload excerpts, file paths, media hashes or raw exception
strings. The caller is responsible for binding authenticated identity and rate limits
before using this validator.

## Integration points for parallel agents and final integration

1. Agent 04 (recipes), Agent 07 (control), Agent 15 (Lucy), Agent 14 (Rooms),
   and Agent 09 (venues): validate inbound/outbound envelopes at service boundaries,
   derive workspace_id from authenticated permissions, and avoid arbitrary extension
   dictionaries. Independently test each producer against this schema; update the
   allowlisted versioned contract only with privacy review.
2. Agent 01 and Agent 05: enforce local DSP execution and output existence on real
   local files, not cloud rendering. Agent 18 must independently disable all hosted
   audio workers and egress credentials; these Python guards are defence in depth.
3. Final integration owner: install bounded request-body middleware *before*
   FastAPI/Pydantic JSON parsing for all relevant cloud endpoints, reject multipart,
   unexpected binary media and unsafe JSON attachments globally, and install outbound
   telemetry/AI egress scrubbers. Existing upload Pydantic parsing happens before the
   route-local guard; the current LF-02 route guard is not a global request-size limit.
4. Agent 17: grandfather historical account exports, run customer-linked asset
   reconciliation, track unresolved recordings and independent release gates. Agent 18
   retires R2 credentials/buckets only after successful migration, lawful retrieval
   and validated local-engine parity.
5. The strict cloud policy is keyed to SELECTA_ENV. Deployment verification must
   prove this variable is set to production/staging, that the sealed phase remains in
   effect, and that no unowned direct ObjectClient, proxy or telemetry route bypasses
   the gate.

## Negative verification

New tests under tests/test_lf02_*.py cover hostile JSON, nested base64 and hex
audio, unsigned or oversized bodies, file paths in diagnostics, duplicate keys,
unknown fields, tenant mismatches, wrong schemas, fail-closed rollout stages,
deadline expiry, signed PUT refusal, sealed route behaviour and approved retrieval.
Existing tests/test_cloud_upload_api.py, test_cloud_playback_api.py,
test_cloud_storage_s3.py and test_cloud_r2_sigv4.py provide legacy compatibility
coverage when running in standalone mode.

Not claimed verified here: comprehensive cross-route packet capture, all cloud
writer paths, infrastructure retirement, account export migration, legal/licensing
reviews or production rollout. Those are explicit independent release gates, not
covered by merely creating this branch.
