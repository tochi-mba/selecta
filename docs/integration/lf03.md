## Public interface for Agents 04, 09, 10–14

```python
from pathlib import Path
from selecta.lf_catalogue import (
    LocalCatalogue, MatchState, MixOccurrence, RecordingRef,
)

with LocalCatalogue(
    Path("/private/engine-state/catalogue.sqlite"),
    workspace_id="workspace_a",
    device_id="device_a",
    freshness_seconds=300,
) as catalog:
    source_id = catalog.add_source(Path("/authorised/local/music"))
    while not catalog.scan_step(source_id, max_entries=256).complete:
        pass

    # Example for a recording first created from this engine's own audio.
    local_file_id = catalog.list_local_instances(source_id)[0]["local_file_id"]
    reference = catalog.mint_local_recording(local_file_id)

    # Agent 04 owns the immutable recipe structure and IDs:
    occurrences = [
        MixOccurrence("occurrence_01", reference),
        MixOccurrence("occurrence_02", reference),
    ]
    report = catalog.resolve_recipe(
        "revision_01", occurrences,
        zone_id="zone_a", policy_generation=None,
    ).to_cloud_dict()
```

The `LocalCatalogue` constructor is scoped to one workspace and device. Cross-workspace references are rejected; the private SQLite path **must not** be in a cloud-synced directory. Any remote-controlled source registration must first go through a local, authorised folder-picker; `add_source`, `relink_source`, `list_local_instances`, `invalidate_path` and `candidate_matches` are local-only calls. Never pass arbitrary remote input to those APIs.

### Identity

- **`RecordingRef(workspace_id, canonical_track_id)`** is an opaque, workspace-scoped recording identifier. It is *not* a path, global hash, local row ID, cloud asset, ISRC or mix position.
- **`MixOccurrence(occurrence_id, recording)`** identifies one distinct sequence occurrence. Two occurrences may intentionally refer to one recording.
- **`local_file_id`** is private to the device DB, stable through inode-based moves, verified source-root relocations and reconnects. Two physical copies (even byte-identical copies) have different IDs when concurrently present.
- **Content revision** increments when bytes, decoder state, permissions, missing state or watcher invalidation change. Recipe IDs/history are not mutated.

### Verified vs unverified recording

`bind_recording(recording, file_id, kind=...)` defaults to **candidate**, which is never playable.

| State | Evidence and semantics | Can schedule? |
| --- | --- | --- |
| `exact` | Private local SHA-256 evidence equals freshly verified file bytes; `mint_local_recording` does this for newly minted canonical IDs | Yes, subject to local policy |
| `verified_equivalent` | Explicit approval of a locally checked equivalent encoding and edition | Yes, subject to local policy |
| `candidate` | Metadata/ISRC or a user-picked file without exact proof, or bytes changed after binding | No |
| `missing` | Local binding absent or a complete successful scan proved it absent | No |
| `blocked` | Access denied, explicit policy/zone/rights failure | No |
| `incompatible_version` | Unsupported codec, corrupt/unstable media, conflicting remaster/live/radio/clean/explicit edition | No |
| `stale` | Expired verification, source reconciliation required, policy generation mismatch or watcher gap | No |
| `unknown` | Source unexpectedly offline; no trustworthy physical-output claim | No |

The exact-binding digest is a **private local parameter**, never transmitted by cloud or returned in an availability DTO. Neither title, artist, ISRC nor matching duration can elevate a candidate to exact/verified equivalent. Deliberate equivalent approval must happen on the authorised engine; do not treat an HQ metadata edit or room request as approval.

The `Availability.to_cloud_dict()`, `RecipeAvailability.to_cloud_dict()`, and `ScanProgress.to_cloud_dict()` allowlist only opaque workspace/device/track/occurrence/source IDs, states, reasons, timestamps, revisions and aggregate counters. They contain **no local path, storage key, hash, fingerprint, PCM, lyrics, source file ID or audio payload**. Cloud has no global binary-match service.

### Policy and readiness

Call `resolve(ref, zone_id=..., expected_policy_generation=...)` immediately before preflight. Only `availability.playable` qualifies for *media* readiness; an actual speaker/device, transition preparation and output check remain owned by Agent 08/09. A source that is offline/degraded, a stale verification, a changed policy generation, expired rights or explicit-content restriction is non-playable. An earlier success does not imply current readiness.

Agent 04 supplies immutable recipe occurrence IDs and canonical recording IDs; this package does not modify `mix_contract.py`, cloud mix stores, Alembic or old cloud assets. Agent 09 may use `resolve_recipe` for zone-local preflight. UI agents may render the sanitised DTOs and must explicitly show `candidate`/`unknown`/`stale` instead of pretending the venue owns a track.

## Incremental scan and failure semantics

- `scan_step(source_id, max_entries=256, should_cancel=...)` bounds work by directory entries and uses on-disk SQLite cursor/scan queue. Large single directories resume from persisted index. Hashing streams at 1 MiB per read and enforces a configurable maximum media size; processing time is bounded by entries and file-size cap. No symlinks are traversed.
- Scan progress and the queue are durable. A terminated process can resume a partial scan; cancellation keeps previously committed batches but **cannot mark not-yet-seen files missing**. A completed, healthy scan marks missing instances without deleting rows, originals, recipes, queues or user work.
- Offline roots are labelled **unknown**, not missing; failed directory traversal labels the source **degraded** rather than falsely treating unseen files as removed.
- `relink_source` checks at least one private exact-content witness at the new root before changing the source root. Relative paths preserve file instances across drive-letter changes. Renames/moves within a source may preserve identity by inode, or by a single unambiguous missing-path digest witness.
- Content is rehashed during rescans, even if file size and modification timestamp appear unchanged, preventing silent same-path byte substitutions. Hashes, inodes and paths are never exposed in DTOs.
- `invalidate_path` fences the local file revision on watcher events; `watcher_overflow` forces a complete rescan after lost events. `register_dependent`/`dependent_valid` protect local analysis, seam and render cache keys from stale source revisions.
- Permission loss, unsupported codecs, unstable writes and rights/zone policy blocks are explicit states. Reconnecting a drive does not automatically authorise a changed recording.

## Compatibility and release hand-off

The old `selecta.library.scan` browse/search/corrections/analysis/relink workflows remain operational. This addition uses its **own local-only SQLite database** and introduces **no repository migration**. Do not use it to move audio to R2 or exchange media peer-to-peer. Cloud mix backfill, permanent recipe storage and migrations are Agent 04/17 responsibilities.

Focused verification: `pytest -q tests/test_lf03_catalogue.py`; then run existing library suites and Ruff on the owned paths. Cases include identical tags/different bytes, duplicate filenames/content, renamed file, same path changed bytes with unchanged timestamps, drive loss/relink, symlink loops, inaccessible media, unsupported WMA, clean/explicit/remastered mismatch, policy/rights expiry, multi-occurrence recipes, cancellation, large incremental scans, tenant isolation and cloud-payload privacy.

**Known integration gates:** This module is an independently callable local contract, **not yet** wired to new local-engine process, Cloud UI or hosted request routes. Audio decoder validation currently uses an extension allowlist plus successful local read; Agent 01/05 must supply actual engine/FFmpeg decoder capability and playback preflight before enabling real output. Verification timestamps are device-observed; server-confirmed freshness is Agent 07/09's responsibility. Local private database encryption, OS ACL enforcement and full fault-injected platform validation remain deployment gates. No ADR is claimed independently verified until integration tests and device checks pass.
