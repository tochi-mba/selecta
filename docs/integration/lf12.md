# LF12 — device-aware player and remote-control UI

**Branch:** `feat/lf12-player-ui` (forked from ADR SHA `0c114859a4f2f13c264dcbd0cba2808d422a97da`).
**Owned scope:** `CloudTransportDock.tsx`, `useCloudPlayer.ts`, new `cloud/lf-device-control/`, LF12 Playwright files and this note.
**Status:** Client implementation + adapter contract + deterministic fixtures. **Not independently verified** and **not deployable until the Agent 03/07/08 protocol routes and release gates exist**. No ADR checklist completion is claimed.

## Entry and compatibility

When `account.features['local_first.player_v1'] === true`, `CloudTransportDock` renders the new player instead of `PlayingBar` and the hosted-media `<audio>` element. The shared `useCloudPlayer` hook remains callable by older Library views but becomes **fail-closed**: no playback-proxy request, prefetch, browser autoplay or R2 URL in LF mode. When the explicit flag is absent/off, legacy hosted playback remains unchanged until data migration and retirement are proven. The enclosing CloudApp still mounts the dock under `cloud.single_audio_owner`; Agent 10 must coordinate feature activation rather than changing that shell here. This flag is intentionally **explicit opt-in** rather than default-on.

The new player is a remote metadata controller. Actual audio stays in the authorised local engine (Agent 01/08), never the browser. Two browser tabs can show/control the same speaker but neither can create a second browser audio source. The actual fencing, physical release and generation lock belong to Agent 08; this client never attempts to substitute a timeout or cloud lease for those guarantees.

## Integration endpoints (proposed; schematic ADR contract)

The ADR `docs/adr/selecta-local-first-api-contracts.md` documents logical messages, **not implemented URLs**. `adapter.ts` isolates this temporary URL convention so Agent 07/08/03 can align routes without changing UI logic:

| Method and path (under `/api`) | Response owner | Client expectation |
|---|---|---|
| `GET /lf/v1/devices` | 01/07 | `{devices: LocalDevice[]}`; explicit `this_device`, `role`, local output IDs/health, connectivity and last server-confirmed timestamp |
| `GET /lf/v1/playback/session` | 08 | `{session: LocalSession|null}`; actual local engine observation, speaker ID/name, output ID/name, generation, recipe revision, state, `original_can_be_fenced` |
| `GET /lf/v1/availability?target_device_id=...&recipe_revision=...&output_id=...` | 03/04/08 | exact per-device/recipe/output media and transition readiness, last verified ISO time; **no paths or fingerprints** |
| `POST /lf/v1/playback/preflight` | 08 | opaque preflight ID, expiry, safety decision, target, revision, output and expected generation |
| `POST /lf/v1/control/commands` | 07 | receipt `{operation_id,state,applied_generation,reason}`; versioned, actor-scoped, expiring idempotent command envelope |
| `GET /lf/v1/control/operations/:id` | 07 | current lifecycle state for delayed/lost ACK recovery; no automatic new-ID retry |

All requests use the normal authenticated `Api` wrapper with `X-Workspace-ID`. Operations also include `workspace_id`, `actor`, nullable `zone_id`, `target_device_id`, `expected_generation`, `expected_recipe_revision`, `created_at`, `expires_at`, `idempotency_key`, `operation_id` and bounded metadata arguments. The server must independently recheck scope, authorization, output health, expiry, generation and transition readiness. The client does **not** send or receive local filesystem paths, raw hashes, PCM, stems, FLAC or media proxies.

## Truth and safety policy

- Speaker and output are reported from local engine observations. If heartbeat/telemetry is older than 15 s, UI says **last reported** and makes no current audibility claim. An output `silent` is not labelled Playing.
- Play Here means **this browser's authorised local engine**, not a cloud audio stream or phone remote. A controller-only device has no local playback option. The current recipe must have fresh (30 s), exact N/M per-device recordings, ready transitions and selected output, and the old speaker must be fenceable.
- Before takeover, fresh current generation/device/readiness are fetched again. Backend preflight must prepare without audible output; only then is a takeover requested. Failed preparation emits **no takeover command**, leaving the original speaker untouched.
- Control Existing Speaker sends a remote play/pause/skip metadata operation. Change Output is distinct and requires independent media/output preflight. Neither operation can play unowned media in this browser.
- Lifecycle reported to UI: `requested`, `prepared`, `queued`, `applied`, `failed`, `expired`, `uncertain`. Cloud `created/accepted/delivered` stay queued. Only a locally applied receipt **plus fresh confirming engine telemetry** can show applied and verified sound. A missing/delayed ACK becomes uncertain, **not assumed successful or retried with a new ID**. Explicit rejected/conflicted/failed/expired reports remain failures.
- Unsafe partition prevents normal takeover; the UI directs operators to reconnect or isolate the original speaker, never to force an optimistic second output.
- Browser audio elements and autoplay are absent in LF mode. Buttons enforce one in-flight operation per tab; server generation/idempotency fencing must resolve cross-tab or cross-device races. MediaSession handlers are installed only in the LF dock and removed on unmount; Space and Right Arrow work within focused remote panel without overriding input/select/button controls.
- The old library audio hook is deliberately fail-closed for LF; actual local playback selection must be routed through the Agent 10/11 recipe/device controls when their integration lands.

## Test commands and evidence

From `web/` after dependencies are installed:

```bash
pnpm exec vitest run src/cloud/lf-device-control/contracts.test.ts src/cloud/lf-device-control/useLocalFirstControl.test.tsx
pnpm exec playwright test --config lf12.playwright.config.ts
pnpm build
```

The dedicated Playwright config is placed **outside web/src under web/ (shared configuration remains unchanged)**, so the shared Playwright configuration stays under Agent 19's ownership. It runs an isolated Vite harness on port 5182; the fixture uses synthetic metadata, not commercial recordings or the real engine. Browser scenarios include separate contexts, missing tracks/disconnected source, partitioned old speaker, destination offline, controller-only phone, delayed acknowledgements, output preflight failure, reconnection/staleness, live announcements and forbidden media URL checks. Hook tests cover refusal and command-envelope safety, plus negative R2 proxy calls.

**Limitations and integration gates:** Tests in these files are deterministic client/harness checks; they do not establish a functioning hardware takeover, an Agent 07/08 server integration, production legality, offline engine continuity, true audible monitoring, verified multi-tab server fencing or an independent release signoff. Agent 19 should import this runner into its full release matrix and add hardware/network fault tests. Agent 08 must supply real fencing and a fresh local audio observation. Agent 07 must expose scoped command and operation APIs. Agent 03/04 must expose exact per-device readiness. Agent 10 must wire selected devices and recipes through the shell, without re-enabling hosted audio. No migrations or unrelated code are changed.

## Rollout and rollback

Keep `local_first.player_v1` off until scoped protocol compatibility, realistic hardware output checks, negative media egress, feature/plan gating and data migration are independently verified. On rollback, disable the flag **only while legacy hosted-media operation is still explicitly approved and available**; never silently resurrect R2 after a no-hosted-audio release gate. Local metadata and historical recipes remain untouched.
