## Local contract

`ArtifactSpec(kind, source_revisions, versions, settings, models)` hashes canonical, sorted
JSON with schema=1 and SHA-256 recording/content revisions, rendered settings, renderer
and analysis compatibility versions and model checkpoints. Supported local classes:
`preview`, `seam`, `stem`, `export`. Source entries are SHA-256 content digests,
**never** paths or title-only guesses. Different content, a renderer/analysis/model
upgrade or changed settings yields a different artifact identity.

`LocalArtifactStore(settings.home / "lf_artifacts")` owns:

- `cache/<identity>.<kind>`: evictable, only in Selecta's private derived-artifact folder.
- `records/<identity>.json`: **device-local** manifest (includes the private file path,
  byte checksum, source revisions, compatibility, and validation checksum). Never
  upload the manifest or give it to a controller.
- A user-selected **permanent** export at an explicit local destination. Exports
  cannot be published into the cache and cannot be overwritten via this API.
- `public_state(identity, device_id=...)`: device ID, artifact ID, type, state,
  size, storage class and completion time; no media, paths, source hashes, signed
  URLs or download links. Cloud/controller code must use this projection **only**.
- `invalidate(source_revisions=..., versions=...)` and
  `mark_source_missing(source_key)`: mark affected outputs stale, preserving
  original media, user's saved exports, and immutable recipes.
- `evict(bytes_needed)`: evicts only records explicitly designated `cache`,
  confirming the file remains under the owned cache root. Never traverses
  library folders, deletes source audio, or removes permanent exports.
- `recover(default_exports)`: clears abandoned `*.part` cache/staging files and
  only narrowly named temporary default-export files. Completed exports stay.
- `reserve(bytes, destination)`: checks unreserved space for concurrent writers
  in this engine process, attempts same-filesystem cache eviction under pressure
  and fails *before writing* if it cannot obtain the estimated space. A different
  process can still consume space; ENOSPC at any later write is handled.

`publish(spec, writer, destination=..., validate=..., estimated_bytes=..., cancel=...)`
writes to an unpredictable same-filesystem temporary file, checks cancellation,
requires nonempty regular output, applies the caller's decoder/format validator,
computes a byte SHA-256, fsyncs the staged output, publishes atomically with a
**no-clobber hard link** for permanent exports (`os.replace` only for cache), then
atomically registers device-private provenance. Writer failure, bad format, denied
destination, cancellation, source mismatch and disk full leave no final artifact.
A failure writing the manifest after output publication may leave a valid, untracked
user export: do **not** delete it automatically; reconcile or choose a different
export destination. The format validator is a required caller concern.

### Existing export route

`/api/exports/jobs` remains compatible with the existing standalone and durable
local job contracts. Agent 01's local engine must explicitly set
`ctx.local_first_artifacts = True`, `settings.local_first_artifacts = True`,
or the server-process `SELECTA_LOCAL_FIRST_ARTIFACTS=1` environment flag
(an engine-owned capability, not an HTTP client-provided flag) to enable the
stricter local-first path. This is a staged
migration switch, not a promise that all existing hosts already use the new
publisher. Existing `ctx.durable_exports` remains delegated to its own owner.

With the capability enabled, the route takes the existing immutable sequence
and seam-key snapshot. After all seams become ready, it hashes **actual song
bytes and transition clip bytes** on the engine; it rechecks them after rendering
and rejects changed sources. It reserves space, renders using the unmodified
`mix.export_snapshot` mixer, decodes the entire staged FLAC through the existing
`verify_export` validator (44.1k/other configured sample-rate, two-channel,
16-bit FLAC), and only then publishes the final permanent file and records the
existing decoded PCM checksum, revision and job progress. No new audio pipeline
or algorithm replaces the existing mixer. Encoding cancellation is cooperative
at publication boundaries: a concurrent encoder is not terminated mid-call but
its unpublished output is discarded when cancellation is observed.

The new `GET /api/exports/local-artifacts/{artifact_id}` route returns only
the `public_state` projection. It is a **local-engine API**, not a cloud media
download endpoint. Do not proxy audio files or device-private manifests through
the cloud. Device identity comes from the trusted runtime context, not the
request.

### Boundary with Agent 05

`lf_artifacts.work_adapter.to_local_work_output(spec, record)` is a one-way
local-only bridge to the existing `selecta.work.ports.ArtifactOutput` and
`selecta.work.provenance` validation. It does not edit scheduling or work
provenance files. Agent 05 should call it only after the job has executed on the
authorised device; its `keys` field is a **local path**, never a value to submit
to a cloud control plane. `stem` maps to the legacy work-port kind `stems`
and requires model provenance. Agent 05 must wire all other seam/stem/preview
producers through this store in its own integration work.

### Boundary with Agents 01/03/04/17

- **01:** sets local capability, engine identity and storage locations; controller
  devices must not invoke a renderer lacking authorised local audio.
- **03:** provides canonical recording and source revision identities, remaster
  rejection, current availability and source-loss/change invalidation events.
  Until that contract arrives, the export adapter hashes the actual local bytes
  instead of assuming a song ID is a stable recording.
- **04:** supplies immutable portable recipe identity; existing frozen export
  revision remains intact until that migration is implemented.
- **17:** owns historical cloud account ZIP and asset migration. This branch
  deliberately does not edit `routes/cloud_export.py` or migrate old cloud
  media. Do not retire old compatible routes without migration gates.

## Tests and verification

`python -m pytest -q tests/test_lf06_artifacts.py tests/test_lf06_routes.py`
tests deterministic identities and local export routing,
preview/seam/stem cache, no-clobber exports, validation-before-publish with
synthetic stereo FLAC, disk reservations, ENOSPC during write, interrupted
rendering, destination permission errors, corrupt content/checksum, cache
eviction, renderer and recording revisions, source disappearance, cancellation,
partial recovery, ownership preservation and controller-safe metadata.

Also run existing `tests/test_flow_export_jobs.py`,
`tests/test_sf0246_frozen_export.py`, `tests/test_export_validation.py` and
`tests/test_local_durable_jobs.py` to check that standalone/durable legacy
behaviour has not regressed. No commercial audio belongs in tests.

### Rollout and rollback gates

1. Run independent tests on Windows/NTFS and Linux/ext4, including read-only
   destinations and interruption after successful encode but before publication.
2. Verify source binding and recipe version contracts from Agents 03/04,
   and local scheduling handoff from Agent 05; independently audit metadata-only
   controller transport and no-audio egress.
3. Opt in one local engine behind the capability, compare known FLAC sample
   checksums, recovery and completed-job visibility, and validate restart.
4. Roll back by turning **off** `ctx.local_first_artifacts`; the legacy export
   route, user files, cache, and saved exports remain. Never reverse a migration
   by deleting music or user-selected outputs.

### Known limits requiring final integration

Reservations coordinate only writers sharing the `LocalArtifactStore` instance
within one process; cross-process/fleet quotas require Agent 05's scheduler.
The existing durable-export implementation bypasses this new publisher until
its owner integrates the adapter. Cancellation is cooperative rather than an
interrupt of a monolithic FFmpeg/mixer call. Failures creating the local manifest
after successful atomic file publication need reconciliation by Agent 05.
There is no evidence of independent multi-device verification in this PR.
