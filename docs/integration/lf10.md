## Scope and rollout

The existing Cloud `Page` type and URLs are retained: `/`, `/listen`, `/library`, `/upload`, `/uploads`, `/account` and `/account/billing`. Standalone Selecta remains a separate runtime. `/upload` and `/uploads` now open **Connect local music** for explicitly enabled workspaces; neither path creates or resumes multipart cloud uploads when the local-first flag is active. Legacy workspaces and their historical uploads remain untouched.

Local-first UI is **opt-in** via `/api/account.features['local_first.personal'] === true`. This is necessary while Agent 01/03/07/04/11/12/16 services and migration tools remain under construction. The Cloud shell overrides the legacy `cloud.uploads` feature gate only for `library` and `uploads` in these opted-in workspaces. This allows the new local source UI even if the historical upload entitlement is switched off. Do not enable the flag in production before the API contract is implemented and the old hosted-media actions are secured or decommissioned.

Agent 10 exclusively changes Cloud shell, legacy upload/library wrappers, new `lf-personal/` modules, dedicated tests and this note. Agent 11 owns saved mix/Studio UI, Agent 12 player, Agent 16 billing; no files from their ownership were edited.

## Proposed version 1 metadata API adapter

The ADR contracts are **schematic** and contain no settled REST route definitions. All provisional endpoint choices are isolated in `web/src/cloud/lf-personal/contract.ts`, so the integration owner can replace them without scattering guesses through UI code.

| Provisional route | Purpose | Cloud audio/file safety |
|---|---|---|
| `GET /api/local-first/personal/snapshot` | Single bounded snapshot for devices, approved sources, recent recipe readiness, current playback owner and local storage diagnostics | Never include files, paths, fingerprints, PCM, stems, signed media URLs or arbitrary reason text |
| `POST /api/local-first/pairings/claim` | Submit short-lived pairing code; server must validate actor/workspace/device scope and expiry | Code only; success is merely a request, not verified audible playback |
| `POST /api/local-first/devices/{device_id}/scan` | Request a scan by the **authorised local engine** | Opaque device ID and schema version only; no path or direct filesystem command |

Snapshot shape, version 1 (all displayed strings use a conservative allowlist):

```json
{
  "schema_version": 1,
  "devices": [{
    "id": "desk-1", "display_name": "Studio PC", "role": "engine",
    "connectivity": "online", "engine_state": "ready",
    "output_state": "verified", "last_verified_at": "2026-11-13T20:00:00Z",
    "verified_tracks": 5, "total_tracks": 8, "platform": "windows"
  }],
  "sources": [{
    "id": "source-1", "device_id": "desk-1", "display_name": "Local Music",
    "state": "source_disconnected", "total_tracks": 8,
    "analysed_tracks": 5, "unsupported_tracks": 1,
    "last_scanned_at": "2026-11-13T20:00:00Z"
  }],
  "recent_recipes": [{
    "recipe_id": "mix-1", "revision_id": "rev-1", "title": "My mix",
    "target_device_id": "desk-1", "verified_tracks": 5, "total_tracks": 8,
    "status": "missing", "last_verified_at": "2026-11-13T20:00:00Z"
  }],
  "playback_owner": { "device_id": "desk-1", "output_name": "Speakers", "status": "playing" },
  "local_storage": [{ "device_id": "desk-1", "used_bytes": 1, "free_bytes": 1000, "cache_bytes": 0 }]
}
```

The snapshot parser ignores all undocumented properties, rejects unsupported versions, bounds lists, guards invalid counts, refuses path-like display labels and declines to infer readiness from a song count. Freshness is 120 seconds for presentation, **never** a backend guarantee. Missing/stale source data and missing engine are not converted into an empty or deleted library.

The hook aborts reads at six seconds and allows retry, visibility resync and online restoration. It retains old data only with a stale warning. `404` or `501` means the local-first device service is unavailable, not that user music is missing.

## Experience and compatibility

- Home includes selected device, recently verified tracks/output, actual playback owner (when reported), hardware disk/cache, a recovery journey, and most recent metadata recipes. Selection is stored per workspace as an opaque device ID only.
- Onboarding distinguishes **Use this computer**, **Pair an existing speaker**, and **Controller only**, with install guidance, local folder consent, local analysis, real-output verification and pairing requests. A localhost link opens the **browser's** machine. Cloud UI cannot and must not browse a remote engine filesystem.
- Library presents selected-device source inventory and explicit connected/disconnected, permission, scanning, incomplete-analysis, unsupported and stale states. No remote local paths or raw API error content are rendered. Requesting a rescan does **not** mark it complete.
- Existing cloud APIs and multipart upload logic remain behind the legacy branch for historical accounts and migration. Existing local standalone entrypoint is unchanged.
- The previous Cloud transport dock, cloud-backed Listen and MakeCloudMix components are **not mounted in flagged local-first mode**, to prevent legacy hosted-audio requests. The old `/listen` route remains navigable, with a truthful link to the local engine. **Agent 11 and Agent 12 must restore the full connected Studio/Listen experience using their local-first components before rollout.** The shell does not pretend that placeholder is product parity.
- Existing Rooms card, settings, Admin, WorkOS, sign-out, account-problem handling, legacy deep links and billing route remain accessible. The billing component remains Agent 16's integration responsibility; do not claim the plan transition is complete here.

## Safe rollback

Remove the `local_first.personal` account flag to return to the historical UI **only before** hosted music services are retired and only where a migration/rights-approved rollback still exists. Do not silently reactivate legacy upload or cloud audio endpoints for accounts that have completed a local-first migration.
