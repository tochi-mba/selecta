# LF16 — Local-first entitlements and business billing integration

**Base:** PR #64 ADR commit `0c114859a4f2f13c264dcbd0cba2808d422a97da`
**Branch:** `feat/lf16-billing` · **Owners:** billing/usage and dedicated Billing/Meters UI.
**ADRs:** 0470 (personal plans), 0471 (business quantities), 0483 (plan/flag compatibility).

## What this branch implements

- `billing/plans.py`: **explicit** v2 plan envelopes with zero hosted-audio
  storage, upload, analysis, speculative CPU and export-retention entitlements.
  V1 `CATALOGUE`, `plan_for(id)`, existing Stripe price mappings, legacy grants,
  paid subscriptions, staff overrides and checkout prices **do not change**.
  `plan_for(id, 2)` is version-qualified and not the default. Local files,
  analyses, stems and exports are not cloud subscription resources.
- `billing/local_first.py`: immutable versioned contract for hosted recipe
  sync/history, remote control, managed devices, Rooms, collaboration, hosted
  Lucy and support. `effective_contract(id, version)` fails closed to *legacy*
  for absent/unrecognised versions; a v2 benefit is only assigned on exact v2.
  `migration_eligible` requires explicit customer approval, commercial
  approval, compensating any legacy purchased benefit and verified local parity.
  `decide_access` keeps plan, flag, role, device capability, verified media and
  venue policy independent; commercial access never proves local playback.
- `billing/stripe_sync.py`: version validation for `SELECTA_STRIPE_PRICES` so a
  typo cannot grant a phantom plan. **Existing v1 map entries remain v1**. Raw
  Stripe subscriptions, webhook signature verification, event dedupe, re-fetch
  on out-of-order delivery, status lifecycle and outage hold remain in the
  existing implementations; no Stripe write API was added.
- `billing/local_first.py`: exposes `effective_contract(...).public_payload()`
  for integration into the existing authenticated account response. It returns
  `model`, `plan`, `plan_version`, `migration_required`, a truthful
  `storage` value and hosted v2 benefits. `usage/hosted_ai.current_usage()`
  provides cloud AI usage. **No new HTTP route** was mounted because Cloud
  strictly requires its API routes to be registered in the global flags
  registry, which Agent 16 does not own.
- `billing/business_quantities.py`: strict read-only translator for approved
  Stripe business price-to-SKU mappings (venue, independently audible zone,
  staff seat, managed device, Room). Unknown prices/mixed versions fail closed
  for *new* provisioning. Zero/negative and malformed quantities are rejected.
  Past-due grace and account-state freshness affect provisioning, **not** the
  instruction to an already playing local engine. A duplicate physical output
  cannot be counted as two independently audible zones. Billing never declares
  an offline venue healthy.
- `usage/hosted_ai.py`: request ceiling, UTC-month spending allowance, atomic
  tenant-scoped idempotency marker in the **existing** `allowance_counters`
  table, and append-only `usage_ledger` cost entry. Costs use **integer
  micro-USD** for enforcement, converted to USD for the cost ledger. The
  idempotency marker hashes the operation ID and workspace; no prompts, audio
  paths, PCM or personal content go into billing usage.
- `web/src/cloud/Billing.tsx` and `Meters.tsx`: v1 subscriptions are labelled
  legacy hosted-audio plans; v2 subscriptions show device-local storage and
  compute *without* obsolete cloud-audio meters. Hosted Lucy remains a cloud
  service. Unapproved v2 purchase prices are not offered as fake checkout SKUs.

## Contract/version matrix

| Source of grant | Effective version | Behaviour |
| --- | --- | --- |
| Existing Stripe price map with version 1 | v1 | Existing purchased GB, checkout consent, subscription and grace rules remain intact |
| No snapshot / Free default / staff override without a version | v1 | No silent local-first migration |
| Explicit approved Stripe price mapping with version 2 | v2 | No hosted audio allowance, new hosted services contract |
| Unknown paid price, missing future contract or stale payment state | Not granted / read-only | Fail closed for new capacity; never command a local speaker to stop |
| Version newer than supported UI | Compatibility notice | UI hides unapproved checkout; update client before plan changes |

The separate v2 personal service budgets and business quantity mapping are
**provisional technical defaults**, not approved retail prices, published
customer contracts, or an authorisation to change production subscriptions.

## Business terms and accounting

`from_stripe(...)` receives a **freshly re-fetched** Stripe subscription and an
operator-approved mapping of each exact price ID to a v2 SKU and quantity. It
does not mutate Stripe or calculate charge prices or service credits. The caller
must supply an authoritative `past_due_since` before applying a 7-day grace;
any stale billing snapshot blocks **new provisioning**, not emergency local
operation. A reduction from three zones to two reports overage, but the venue
engine decides safe, rights-compliant continued playback. The user must be
offered an explicit remediation path rather than silently turning off a speaker.

**Required business persistence:** Agent 04 (sole schema migration owner) must
provide versioned org commercial terms, approved price/SKU mappings, quantity
revision and commitment/credit fields, plus an audit trail. Avoid using plan
flags or device heartbeat as a substitute for purchased counts. Agent 09 must
wire provisioning/admission and zoned playback checks to the business
reconciler; Agent 13 owns the business console and notices.

## Hosted AI contract and integration boundary

`hosted_ai.preflight(conn, workspace_id, v2_benefits,
maximum_cost_micros=...)` runs **before** a paid provider request. The amount
must be an integer estimated cost and cannot exceed a per-request ceiling or
remaining monthly allowance; standard technical defaults are 250 cents/month,
50 cents/request; premium 1000 cents/month, 200 cents/request. These are
provisional and should be reviewed before any v2 commercial launch.

After success, `hosted_ai.charge_once(conn, workspace_id, v2_benefits,
operation_id=..., actual_cost_micros=..., provider=..., model_class=...)`
runs in a transaction. A replayed operation ID is a no-op **even across month boundaries** because the idempotency marker uses a permanent global period key; only the spending counter resets monthly.
Persisted ledger details only contain provider/model labels and contract name.
**Integration needed from Agent 15:** enforce `preflight` immediately before
provider invocation, bound maximum generated tokens, pass trusted provider
costs to `charge_once`, handle unknown over-ceiling final costs without
silently posting a charge, and bind retry IDs to the same provider request.
For requests spanning calendar-month rollover, the integrating gateway must
bind charges to the original authorised budget period and reconcile any
reserved-but-failed provider cost. The operation key is de-duplicated globally,
but the monthly allowance period for late settlement is the time of settlement
until this integration is complete. Local DSP never calls this
meter. Existing v1 Lucy turn quotas remain intact.

  music` / `Upload tracks` with a device-local source action, and hide legacy

The Python test files assert legacy version compatibility, unknown prices,
plan/flag/media independence, business quantity changes, offline capacity,
payment grace, AI allowance exhaustion, tenant isolation and idempotent billing
ledger writes. Existing webhook tests continue to cover signature verification,
duplicate and out-of-order events. **A passing complete end-to-end release gate
is not claimed here.** Independent testing, legal/customer notices, contract
approval, migration drill and rollback evidence remain required by ADR-0470,
ADR-0471 and ADR-0483.

## Rollout and rollback

1. Ship v2 definitions and read-only contract introspection behind existing
   services while leaving all live Stripe prices mapped to **v1**.
2. Independently validate the future SKU mappings, customer contracts, privacy,
   capacity/reconciliation and AI budgets against real billing records in
   staging. Never use production payment keys in tests.
3. Obtain customer consent and commercial/legal approval, compensate purchased
   benefits, verify device-local parity and only then opt a cohort into v2.
4. Roll back a cohort through an approved, audited contract/Stripe mapping
   process; the unchanged v1 catalogue and immutable snapshots retain history.
   Do not invent restored music or delete user media as a rollback shortcut.

**No live subscriptions, price IDs, customer contracts, webhooks, migrations or
CloudApp shell code have been modified by this branch.**

**Flag registry handoff (non-Agent16 owner):** register a read-only
`GET /api/billing/contract` under the appropriate global flag if an API
endpoint is chosen, then mount it only when `assert_cloud_api_routes_owned`
passes. The integration must check workspace membership and return plan
version and hosted AI usage; never expose local paths or audio fingerprints.
