# LF11 — Device-aware Studio and recipe repair integration

**Branch:** `feat/lf11-studio-ui`  
**ADR baseline:** `0c114859a4f2f13c264dcbd0cba2808d422a97da`  
**Scope:** `MakeCloudMix.tsx`, `web/src/views/**`, `web/src/cloud/lf-mix-repair/**`, LF11 E2E spec and this document only.

## Delivered front-end behavior

- Saved recipe cards support a verified `N/M` count **for the selected device and exact revision**; the default is **Unverified**, never inferred from uploaded cloud assets.
- The editor remains available when zero, some, or all recordings are missing. Legacy immutable revision and parent history endpoints are left intact. Reordering, naming, restoring previous revisions and existing local Studio views are preserved. Local editor controls additionally expose undo/redo.
- Availability is one of **Ready, Missing, Candidate, Version Mismatch, Source Disconnected, Permission Required, Unsupported, Blocked, Unknown, Cache Invalid**. Each result is occurrence-scoped so repeated recordings are not conflated.
- Every local verifier answer is validated against workspace-selected device, mix ID, immutable revision, ordered occurrence IDs and total. Unknown or mismatched answers are rejected. Results expire after 120 seconds; disconnected engine/source and controller offline are treated as unverified.
- Four distinct capabilities are shown: **Editable**, **Renderable**, **Auditionable** and **Playable**. Only Editable is always true. Playback additionally requires verified engine health, source, policy, cues, seams, real output and a free committed window. No fake waveforms or audio preview components are constructed.
- Repair UI offers Control existing device, Reconnect source, Authorise source, Locate local recording, Review alternate version and Create temporary variation. Device-executed operations are **disabled** until a real authorised local repair executor is injected. The file picker never sends files to the cloud API, reads media bytes, or converts guessed matches into verified recordings.
- Temporary variation is a separate unsaved plan with only verified local occurrences; copying it to an editor draft does not mutate the original. Explicit save uses the legacy revision endpoint with `base_revision` optimistic concurrency. Candidate substitutions are never applied silently; a source replacement invalidates previews, cues and dependent seams until local regeneration.
- Legacy standalone timeline, manual cue, stem, seam, drafts, export and request features remain untouched; this PR does not replace or delete them.

## Strict integration contract (for Agents 03, 04, 07, 08 and 12)

The ADR commit contains **no implementation** of an authoritative per-device verifier. To avoid inventing server truth, this UI is fail-closed and the new calls are gated behind an **explicitly true** `account.features['local_first.mix_readiness']` flag. Until the local-first backend is integrated the connected UI shows **Unknown** and local repair actions remain disabled.

Proposed, **not yet implemented**, read-only control-plane adapter routes:

```text
GET /api/local-first/devices
=> { devices: [{ id, name, controllerOnly, connected, outputVerified }] }

GET /api/local-first/devices/{deviceId}/mixes/{mixId}/availability?revision={revision}
=> {
  device_id, mix_id, revision, checked_at, local_verification,
  engine_healthy, source_connected, output_verified, policy_allowed,
  playback_window_free,
  tracks: [
    {
      occurrence_id, state, reason, verified_at,
      candidate_id, candidate_version, candidate_explicit, equivalent_verified,
      cue_valid, seam_valid, preview_valid
    }
  ]
}
```

Timestamps in this adapter are Unix **milliseconds**, including all local verification timestamps. `tracks` must include every ordered recipe occurrence, including duplicates; a missing row fails the entire verification. All claims must come from the **authorised local engine**, not from cloud object storage, metadata similarity, a player heartbeat or recipe save acknowledgements. Only metadata and opaque occurrence IDs may traverse this boundary: **never upload raw audio, waveforms, fingerprints, local paths, stems or reconstructible audio features**.

`DeviceMixRepair` accepts `onRepair?: RepairExecutor`. A future authorised local-engine adapter must enforce tenant/device/zone permissions, idempotency, fenced ownership generations, per-source rights and exact recording identity, then explicitly re-verify. The adapter must not send browser `File` objects to Cloud. Control existing device and transfer ownership belong to Agents 07/08/12; this PR does not bypass them. Source selection and path verification belong to Agent 03, and canonical recipe substitutions / immutable parent chain to Agent 04. Do not wire the repair executor to a cloud upload endpoint.

## Safety and preservation matrix

| Condition | UI action |
| --- | --- |
| 5 ready / 2 missing / 1 candidate | 5/8 only while verification fresh; all three unresolved positions shown |
| Wrong clean/explicit, radio/live/remaster or uncertain identity | Candidate remains unresolved; no automatic swap |
| Source or engine disconnect, old telemetry or offline browser | Count becomes Unverified, Playable/preview disabled, editing still available |
| Preview/seam/cue cache after substitution | `Cache Invalid`; dependent cue/seam/preview invalidated |
| Controller-only or no verified output | Editing only; no false speaker claims |
| Committed playback window or disallowed content | Playable remains false |
| Concurrent revision write | Existing optimistic `base_revision` save refuses 409; original history preserved |
| Undo/redo, prior revision restore, drafts | Preserve existing editing history; no destructive rewrite |
| Missing local backend | Show explicit Unknown and disabled repair transport, rather than pretending to act |
