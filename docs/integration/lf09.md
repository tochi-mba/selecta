# LF09 — speaker-owned venue execution (draft integration contract)

**Base:** `docs/local-first-cloud-rearchitecture-20261113` @ `0c114859a4f2f13c264dcbd0cba2808d422a97da`.
**Scope:** ADR-0467, ADR-0468, ADR-0474. **Physical hardware gate: OUTSTANDING**.

## Runtime and authoritative facts

`selecta.lf_venue` is a **device-local** venue runner, SQLite WAL state/checkpoint and append-only acknowledgement journal. The authorised local engine (not a browser, Cloud lease or headquarters catalogue entry) owns physical playback. A `LocalAudioPort` implementation supplied by Agent 08/01 must implement `preflight`, `prepare`, `start`, `stop`, and `probe`; `EngineAuthorisation` must bind workspace, venue and paired engine. **This branch does not provide a physical audio adapter and must not be marked production-ready until the adapter is wired and tested.** `VenueRunner.step()` is the supervised caller; its loop must run on the venue engine host and connect actual `ended` callbacks. Never use it inside the control-plane server.

The local SQLite DB persists venue configuration, IANA timezone, weekly opening periods (including overnight and DST folds/gaps), daypart policy, source eligibility and local-only file bindings, output/channel claims, current/next-three committed horizon, prepared local DSP handles, planned IDs, playback generation, last verified physical output, checkpoints, and play journal. The filesystem paths and SHA256 hashes live **only** in the local DB. `business.lf_status.device_status` is safe-to-send telemetry (IDs/state/health only); never send `tracks` or `prepared` handle fields over the network. Programme IDs are metadata, not proof of recordings.

`plan` fences the current+next-two committed IDs during an active session; `prepare` verifies exact local SHA256 recordings under authorised source roots, policy, source eligibility, local physical device preflight, and DSP readiness without audible output. `ended` is only invoked by the authoritative local audio decoder after a real output-completion acknowledgement; otherwise timers/Cloud messages cannot advance the horizon. It may use only locally verified, permitted fallback IDs, and cannot silently replace a blocked artist or clean edit with an explicit version. Current audio remains untouched if an upcoming preparation fails. No R2 media, pre-signed URLs, PCM, stems, fingerprints, or paths leave the device. Agent 04 owns canonical identity schema; this branch accepts a canonical `track_id` and a locally verified revision and must be adapted to its final shape at integration.

Opening hours and rights are rechecked on **every device tick** even without internet. Mid-service rights expiry, policy changes, USB loss and silent physical output cause stopping or an explicit unknown state, never a success claim based solely on Cloud heartbeat. A power-cycle `recover` is attempted once at boot, and only with valid opening hours, policy, rights, engine authority, source integrity, prepared local handle, unused physical output and a checkpoint within source duration. A backward clock jump beyond 120 seconds fences new playback; without secure clock evidence administrators must verify rights/clock before enabling automatic restart. Never replay a queued cloud transport command as recovery.

SQLite output channel reservations prevent two zones claiming the same exclusive speaker; explicit multichannel allocations may use distinct nonoverlapping channel sets. `Limits` checks sample rate, latency, CPU and RAM headroom; `admit_background` returns **zero** until active zones have >=3 verified prepared items. Agent 05 must enforce these limits in its scheduler; this module intentionally does not edit shared scheduling files. Agent 08 owns cross-device audio fencing; local adapter must reject generations below the last applied fence and acknowledge physical release before a takeover. The local journal includes only `started`, `ended`, `stopped`, `failed` acknowledgements; `pending_events`/`acknowledge_events` synchronize IDs idempotently without replaying old transport commands. Integrate with `business.playlog.sync_batch` using venue-scoped event IDs and explicit licensing metadata enrichment, not the local file paths.

## Runner wiring

1. The local-service installer (Agent 01) creates one private SQLite DB per engine, confirms paired device authority, sets true local source roots and registers recordings using exact SHA256 revision evidence.
2. Pass the real local DSP/player implementation from Agents 05/08 as `LocalAudioPort`; the port must route channels to a named *physical* output and report loopback/signal health. `VenueRunner.step()` may auto-start only a previously planned, unstopped, still-authorised venue during open hours; a manual stop remains stopped.
3. Hook physical decoder completion callbacks to `engine.ended(..., generation=...)`; never derive playback advancement from Cloud timers. Bind `business.lf_status.device_status` to Agent 13 HQ manager status, which must label output state `unknown` until confirmed.
4. Wire resource limits to measured device capacity, and schedule DSP work at lower priority than live zones. Upload journal acknowledgements at reconnection without changing local transport state.

## Verification evidence and explicit limitations

Local simulations: `PYTHONPATH=src python -m pytest -q tests/test_lf09_venue.py` — 12 tests pass on isolated source tree. They cover a six-hour offline simulation with 36 real simulated decoder-end callbacks, durable journal deduplication, 20 venues with divergent inventories, separate-zone playback and output claims, 2026 Europe/London DST and Friday overnight opening, policy changes, licence expiry, source loss and SHA tampering, clock skew, power recovery, silent/disconnected output, and CPU scheduling safety. These tests use an **in-memory fake audio port** with synthetic bytes, **not** actual commercial recordings or sound hardware. No cloud media upload exists in the code; integration should add explicit network egress denial tests.
